How DynamoDB Scan Limit Affects Evaluated Items

In Amazon DynamoDB, the Limit parameter on a Scan operation restricts the maximum number of items the database evaluates before applying any filter expressions, rather than dictating the number of matching items returned to the client. This article explains how the Limit parameter functions during a scan, why returned results may be fewer than the configured limit, and how it directly impacts read throughput and pagination.

The Evaluation Process

When you execute a Scan in DynamoDB, the request processes items sequentially through the following pipeline:

  1. Read Items: DynamoDB reads items sequentially from the table up to the number specified by the Limit parameter (or up to the 1 MB data size limit, whichever comes first).
  2. Apply FilterExpression: If a FilterExpression is defined, DynamoDB evaluates the read items against this condition. Items that do not meet the criteria are discarded.
  3. Return Results: DynamoDB returns the remaining matching items to the client, along with metadata about the operation.

Because DynamoDB applies the Limit in step 1, the parameter controls how many items are examined (evaluated), not how many matching items are returned.

ScannedCount vs. Count

The response of a Scan operation includes two distinct metrics that illustrate this behavior:

  • ScannedCount: The total number of items DynamoDB evaluated. When a Limit is supplied, ScannedCount will be less than or equal to that Limit.
  • Count: The number of items that satisfied the FilterExpression and are present in the final result payload.

If you set Limit = 50 on a table scan with a FilterExpression, DynamoDB reads exactly 50 items. If only 5 of those 50 items match your filter criteria, ScannedCount will be 50, but Count will be 5. In cases where none of the evaluated items match the filter, DynamoDB returns an empty list (Count = 0), even though it evaluated 50 items.

Pagination with LastEvaluatedKey

If DynamoDB reaches the Limit value before scanning the entire table or reaching the end of the dataset, it stops the operation and returns a LastEvaluatedKey.

To retrieve the next batch of items, your application must issue another Scan request passing this key into the ExclusiveStartKey parameter. This pagination continues sequentially until DynamoDB no longer returns a LastEvaluatedKey, indicating the entire dataset has been traversed.

Cost and Capacity Consumption

DynamoDB calculates consumed Read Capacity Units (RCUs) based on the total size of all evaluated items (ScannedCount), not the size of the filtered results (Count). Restricting the scan with a Limit parameter helps prevent unexpected capacity spikes by bounding the amount of data processed in a single API call, but filtered-out items still consume read throughput.
