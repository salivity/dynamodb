AWS DynamoDB On-Demand Capacity Billing Model

Amazon DynamoDB on-demand capacity mode operates on a pay-per-request billing model, charging exclusively for the actual read and write operations your application performs alongside data storage. Unlike provisioned capacity, there is no need to forecast throughput or pay for unused resources. This guide breaks down the core mechanics of this pricing structure, detailing how read and write request units are calculated, additional associated charges, and when this model makes the most financial sense.

The Pay-Per-Request Billing Model

When you configure a DynamoDB table with on-demand capacity mode, AWS applies a strict pay-as-you-go, pay-per-request model. You do not allocate read or write capacity units in advance. Instead, DynamoDB instantly scales up or down to accommodate your workload, and you are billed only for the exact volume of requests processed. If your table receives zero requests, your request costs are zero.

How Requests Are Metered

DynamoDB measures request consumption using Read Request Units (RRUs) and Write Request Units (WRUs).

Read Request Units (RRUs)

The number of RRUs consumed depends on the size of the item and the read consistency model:

  • Strongly Consistent Read: One RRU handles one read request per second for an item up to 4 KB in size.
  • Eventually Consistent Read: Consumes half an RRU (0.5 RRU) for an item up to 4 KB.
  • Transactional Read: Consumes two RRUs for an item up to 4 KB.
  • Items Exceeding 4 KB: Require additional RRUs calculated in 4 KB increments (e.g., an 8 KB strongly consistent read requires 2 RRUs).

Write Request Units (WRUs)

The number of WRUs consumed depends on the size of the item and whether standard or transactional writes are used:

  • Standard Write: One WRU performs one write request per second for an item up to 1 KB in size.
  • Transactional Write: Consumes two WRUs for an item up to 1 KB.
  • Items Exceeding 1 KB: Require additional WRUs calculated in 1 KB increments (e.g., a 3 KB standard write requires 3 WRUs).

Additional Costs to Consider

While request throughput is billed on a per-request basis, other standard DynamoDB features incur separate charges under the same overall account bill:

  • Data Storage: Billed per gigabyte-month (GB-month) based on the total size of your table and local secondary indexes.
  • Global Secondary Indexes (GSIs): Creating a GSI on an on-demand table inherits the on-demand pricing model, billing WRUs and RRUs separately for index reads and index updates.
  • Data Protection: Point-in-time recovery (PITR) and on-demand backups incur their own storage-based costs.
  • Global Tables: Multi-region replication charges replicated write request units (rWRUs) for changes synchronized across regions.
  • DynamoDB Streams: Reading data from DynamoDB Streams incurs small request charges per read request.

Best Use Cases for On-Demand Billing

The on-demand billing model is best suited for:

  • New applications with unknown traffic profiles.
  • Workloads with unpredictable, spiky, or intermittent traffic patterns.
  • Applications that spend significant time idle, where paying for baseline provisioned capacity would result in wasted spend.
