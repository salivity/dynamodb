How DynamoDB Manages Encryption Key Rotation

Amazon DynamoDB manages server-side encryption (SSE) key rotation through its tight integration with AWS Key Management Service (AWS KMS). Depending on the type of encryption key selected for a table—an AWS owned key, an AWS managed key, or a customer managed key (CMK)—DynamoDB handles key rotation either automatically behind the scenes or under the user's explicit policy configuration. Importantly, when a key rotates, DynamoDB does not immediately re-encrypt existing data; instead, it uses the new key version for subsequent writes while retaining the ability to decrypt older data using prior key versions.

Encryption Key Types and Rotation Behaviors

DynamoDB supports three key types for server-side encryption, each handling rotation differently:

  • AWS Owned Keys: These keys are entirely maintained and operated by DynamoDB. AWS automatically rotates the cryptographic material on a regular internal schedule. Users do not incur additional AWS KMS charges for these keys, nor do they have visibility or control over when rotation occurs.
  • AWS Managed Keys (aws/dynamodb): These keys reside in your account and are managed by AWS KMS on behalf of DynamoDB. AWS KMS automatically rotates the underlying key material for AWS managed keys once every year (approximately every 365 days). Users cannot disable or alter the rotation schedule for this key type.
  • Customer Managed Keys (CMKs): These keys are created, owned, and configured by you in AWS KMS. With CMKs, you control rotation. You can enable automatic key rotation, which allows AWS KMS to generate new key material at a user-defined interval (between 90 and 2,560 days, with 365 days as the default). Alternatively, you can perform manual rotation by creating a new CMK and updating your DynamoDB table settings to use the new key ARN.

The Mechanics of Envelope Encryption During Rotation

DynamoDB uses envelope encryption to protect data efficiently at scale. Under this model, the AWS KMS key protects a hierarchy of keys rather than encrypting every individual table item directly:

  1. Backing Key Material: When automatic rotation is enabled for a KMS key, AWS KMS creates new cryptographic backing material. The key's metadata, identity, and Amazon Resource Name (ARN) remain identical.
  2. No Full Table Re-Encryption: When a key rotates, DynamoDB does not read and re-write all existing records on disk. Re-encrypting multi-terabyte datasets immediately would cause unacceptable performance overhead and API throttling.
  3. New Writes: New data written to the DynamoDB table is encrypted using fresh data encryption keys (DEKs) generated from the newly active KMS key material.
  4. Reads and Decryption: AWS KMS retains all historical versions of a key's backing material. When DynamoDB reads an item that was encrypted prior to the rotation, KMS uses the specific version of the key material that originally generated the item's DEK to decrypt it seamlessly.

Because the key ARN remains constant during automatic rotation, applications reading from and writing to DynamoDB require no configuration updates, code modifications, or downtime when key material rotates.
