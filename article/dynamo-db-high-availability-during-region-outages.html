DynamoDB High Availability During Region Outages

Amazon DynamoDB Global Tables provide a fully managed, multi-region, active-active database solution designed to deliver continuous uptime and disaster recovery for mission-critical applications. By automatically replicating data across multiple designated AWS regions, Global Tables ensure that if an entire AWS region experiences an outage, applications can seamlessly redirect read and write workloads to healthy replicas in other regions with minimal latency impact and no loss of availability.

Multi-Region Active-Active Replication

DynamoDB Global Tables operate on an active-active model, meaning every replica table in every participating region can serve both read and write requests locally. When a client performs a write operation in one region, DynamoDB automatically captures the change using internal storage engine streams and asynchronously propagates the update to all other replica regions. Under normal operating conditions, this replication typically completes in less than a second. Because every region maintains an independent, fully functional copy of the dataset, no single region serves as a bottleneck or single point of failure.

Client-Side Redirection and Failover Routing

DynamoDB relies on the client application or network-routing layers to detect regional degradation and switch traffic. Tools such as Amazon Route 53 health checks, AWS Application Recovery Controller (ARC), or the AWS SDK with multi-region retry capabilities monitor regional health. When monitoring tools detect that an entire region is unreachable or experiencing elevated error rates, DNS records or application endpoints automatically update to route incoming traffic to the nearest surviving replica region. Because the replica is already actively accepting writes, there is no need for a complex database failover sequence or promotion of a standby instance.

Conflict Resolution via Last-Writer-Wins

In an active-active setup, conflicting updates can occur, particularly during network partitions or regional failovers. DynamoDB handles this using a native "Last-Writer-Wins" reconciliation mechanism. DynamoDB attaches an internal timestamp to every update. If conflicting writes occur across different regions before a failover completes, DynamoDB evaluates the timestamps and persists the most recent write across all replicas. This deterministic approach ensures that all surviving regions maintain a consistent state without requiring manual conflict resolution logic.

Partition Isolation and Outage Containment

Within each AWS region, DynamoDB tables are partitioned across multiple Availability Zones (AZs) by default. The replication engine decoupled across regions ensures that failures inside one region—whether hardware failure, network disconnection, or data-center-level disruption—remain isolated. The storage nodes, partition routers, and replication endpoints of surviving regions continue running independently, completely insulated from the degraded region’s infrastructure.

Post-Outage Recovery and Catch-Up

When the failed region comes back online, DynamoDB Global Tables automatically initiate recovery without administrative intervention. The replication engine tracks the replication watermarks and begins replaying missed updates to bring the recovered region up to date. During this catch-up phase, the recovered region remains accessible for reads and writes, progressively catching up with recent transactions until global data consistency is fully restored.
