DynamoDB Sparse GSI Capacity Calculation

This article explains how Amazon DynamoDB calculates read and write capacity unit consumption for sparse global secondary indexes (GSIs). A sparse index only contains items that feature the index's partition key and sort key attributes. Understanding how DynamoDB measures data sizes, updates, and omissions within these projections enables precise capacity planning and cost optimization.

How Sparse Indexes Determine Write Capacity

DynamoDB consumes Write Capacity Units (WCUs) on a GSI only when an operation on the base table results in an addition, update, or deletion of an item within that index. Because a sparse GSI only indexes items containing the designated key attributes, writes to the base table do not always consume GSI capacity.

  • Omitted Index Keys (Zero WCU): If a base table write (PutItem, UpdateItem) does not include the GSI's partition key (or sort key, if defined), DynamoDB does not write to the GSI. The GSI consumes 0 WCUs for that operation.
  • New GSI Items: When a base table operation introduces the GSI keys, DynamoDB writes the item to the GSI. The consumed WCU depends on the size of the projected item, calculated in 1 KB increments (rounded up).
  • Updating Projected Attributes: If an update changes an attribute projected into the GSI, DynamoDB writes the updated item to the GSI. The WCU consumed equals the size of the new projected item rounded up to the nearest 1 KB.
  • Updating Non-Projected Attributes (Zero WCU): If an update only modifies base table attributes that are not included in the GSI projection, no write occurs on the GSI, consuming 0 WCUs.
  • Removing Index Keys or Deleting Items: If a base table item is deleted, or updated so that its GSI key attributes are removed, DynamoDB deletes the corresponding entry from the GSI. The GSI consumes write capacity equal to the size of the previously existing projected item rounded up to the nearest 1 KB.

Calculating GSI Item Size for Capacity

DynamoDB calculates the size of an item in a GSI differently from the base table. The item size in a GSI includes:

  1. The size of the GSI partition key attribute name and value.
  2. The size of the GSI sort key attribute name and value (if present).
  3. The size of the base table primary key attributes (partition key and sort key) that are automatically projected into the index.
  4. The size of any additional projected attribute names and values (KEYS_ONLY, INCLUDE, or ALL).
  5. An additional 100 bytes of indexing overhead per item.

The total byte count is rounded up to the nearest 1 KB multiplier to determine the base WCU required for each write.

Read Capacity Unit (RCU) Calculation

Read operations on a sparse GSI consume Read Capacity Units (RCUs) only for the items retrieved from the index:

  • Eventually Consistent Reads: GSIs support eventually consistent reads by default. One RCU delivers two eventually consistent reads per second for items up to 4 KB in size. If an item exceeds 4 KB, DynamoDB rounds up to the next 4 KB boundary (e.g., an 8 KB item requires 2 RCUs).
  • Sparse Efficiency: Queries and scans on a sparse GSI consume fewer total RCUs compared to base table scans because DynamoDB only reads items that exist in the index, completely bypassing items that lack the GSI keys.
