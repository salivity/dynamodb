DynamoDB BatchGetItem Consumed Capacity Calculation

Amazon DynamoDB calculates consumed capacity for BatchGetItem operations by evaluating each requested item individually rather than aggregating the total payload size of the batch. The total Read Capacity Units (RCUs) billed for the operation depend directly on the size of each discrete item rounded up to the nearest 4 KB boundary and the consistency model selected for the request.

Per-Item Calculation Model

When executing a BatchGetItem request, DynamoDB processes each item as an independent read. The service does not sum the sizes of all items to determine the total read capacity. Instead, it performs the rounding calculation on every individual item retrieved before adding the resulting capacity units together.

Impact of Read Consistency

The consistency model specified in the request determines the multiplier applied to each item:

  • Eventually Consistent Reads (Default): DynamoDB charges 0.5 RCU for each item up to 4 KB in size.
  • Strongly Consistent Reads: DynamoDB charges 1 RCU for each item up to 4 KB in size.

If an item exceeds 4 KB, DynamoDB rounds the size up to the next 4 KB increment and applies the appropriate rate. For example, an 8.5 KB item rounds up to 12 KB, consuming 1.5 RCUs for an eventually consistent read or 3 RCUs for a strongly consistent read.

Step-by-Step Calculation Example

Consider a BatchGetItem call requesting three items using strongly consistent reads:

  • Item A: 1.5 KB
  • Item B: 3.8 KB
  • Item C: 5.2 KB

The capacity is calculated as follows:

  1. Item A (1.5 KB): Rounded up to 4 KB = 1 RCU.
  2. Item B (3.8 KB): Rounded up to 4 KB = 1 RCU.
  3. Item C (5.2 KB): Rounded up to 8 KB = 2 RCUs.

The total consumed capacity for this batch operation is 4 RCUs (1 + 1 + 2). If calculated using eventually consistent reads, each value is halved, resulting in a total of 2 RCUs (0.5 + 0.5 + 1.0).

Non-Existent Items

If a requested primary key does not exist in the table, DynamoDB still consumes read capacity units to perform the lookup. The service charges 1 RCU (strongly consistent) or 0.5 RCU (eventually consistent) for the attempt, rounding the empty evaluation to a baseline 4 KB read.

Multi-Table Batches

BatchGetItem can query items across multiple tables in a single API call. DynamoDB calculates consumed capacity for each item individually and deducts the corresponding RCUs from the provisioned or on-demand throughput of the specific table from which the item was read. Capacity is not pooled across tables.
