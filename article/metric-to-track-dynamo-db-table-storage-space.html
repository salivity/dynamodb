Metric to Track DynamoDB Table Storage Space

Monitoring storage utilization is essential for capacity planning and cost optimization in Amazon DynamoDB. This article explains the specific Amazon CloudWatch metric used to track the total storage space consumed by a DynamoDB table, how the metric is reported, its limitations, and related metrics for secondary indexes.

The primary metric that tracks the total storage space consumed by a DynamoDB table is TableSizeBytes.

Published under the AWS/DynamoDB namespace in Amazon CloudWatch, TableSizeBytes measures the total size of all data items stored in the specified table, expressed in bytes. This value accounts for the attribute names, attribute values, and internal overhead required to store each item.

Reporting Frequency and Behavior

Unlike real-time request metrics (such as ConsumedReadCapacityUnits or SuccessfulRequestLatency), TableSizeBytes is not updated continuously. Amazon CloudWatch updates this metric approximately once every six hours. Because it provides a point-in-time snapshot rather than a streaming total, brief spikes or drops in data volume will not be reflected immediately on CloudWatch dashboards.

Monitoring Global Secondary Indexes

If a table utilizes Global Secondary Indexes (GSIs), the storage used by those indexes is not included in the base TableSizeBytes metric. Instead, CloudWatch publishes a separate metric:

  • GlobalSecondaryIndexTableSizeBytes: Measures the total size in bytes for a specific GSI associated with the table.

To calculate the full storage footprint of a DynamoDB workload, you must combine TableSizeBytes with the GlobalSecondaryIndexTableSizeBytes values for all GSIs attached to that table.

How to View the Metric

You can inspect TableSizeBytes using several AWS tools:

  1. CloudWatch Console: Navigate to Metrics, select the AWS/DynamoDB namespace, choose the TableMetrics dimension, and locate TableSizeBytes for your table name.
  2. DynamoDB Console: View the "Table details" tab in the DynamoDB console, which displays the latest table size and item count statistics.
  3. AWS CLI or SDK: Run the describe-table command in the AWS CLI to retrieve the TableSizeBytes property directly from the table description metadata, or call get-metric-statistics against the CloudWatch API for historical trends.
