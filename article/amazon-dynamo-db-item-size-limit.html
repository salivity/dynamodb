Amazon DynamoDB Item Size Limit

This article explains the maximum item size limit enforced by Amazon DynamoDB for a single record. Readers will learn the exact byte threshold allowed by the database, how item size is calculated, the performance and throughput implications of large items, and practical design patterns to handle data that exceeds these restrictions.

Amazon DynamoDB enforces a maximum item size limit of 400 kilobytes (KB) for a single record. This limit is hard-coded and cannot be increased by submitting a service quota request. Any attempt to write or update an item that causes the total size to exceed 400 KB results in DynamoDB rejecting the operation and throwing an ItemCollectionSizeLimitExceededException or ValidationException.

How Item Size Is Calculated

The 400 KB limit applies to the entire representation of the item, not just the data values. DynamoDB calculates the total item size by adding the length of all attribute names to the length of their corresponding attribute values:

  • Attribute Names: The length of each attribute name in UTF-8 encoded bytes.
  • Strings: The length of the string in UTF-8 encoded bytes.
  • Numbers: Stored as variable-length attributes, typically taking up to 21 bytes.
  • Binary Data: The exact number of raw bytes in the binary array.
  • Booleans and Nulls: 1 byte.
  • Lists and Maps: Includes the overhead of the structural elements (typically 1 to 3 bytes per element/entry) plus the size of all nested attribute names and values.

Because attribute names count toward the 400 KB boundary, verbose key names can quickly consume significant storage space.

Impact on Read and Write Capacity

Working near the 400 KB ceiling has a direct impact on operational costs and throughput:

  • Write Capacity Units (WCUs): One standard WCU handles one write per second for items up to 1 KB. Writing a full 400 KB item consumes 400 WCUs in a single operation.
  • Read Capacity Units (RCUs): One strongly consistent RCU covers reads up to 4 KB per second. Reading a 400 KB item requires 100 RCUs (or 50 RCUs for eventually consistent reads).

Consequently, storing large items in DynamoDB can rapidly consume provisioned throughput or drive up on-demand billing costs.

Solutions for Handling Data Over 400 KB

When application data exceeds the 400 KB limit, consider the following standard architectures:

  1. The Claim Check Pattern (S3 Offloading): Store the payload (such as large JSON blobs, documents, or media) in Amazon S3, and store only the S3 object key or URL as a string reference within the DynamoDB record.
  2. Data Compression: For large text or JSON structures, compress the data using algorithms like Gzip or Snappy before saving it as a Binary attribute. This often reduces the payload size by 60% to 80%, fitting the item within the 400 KB limit.
  3. Item Splitting: Split large records into multiple items across a partition key and sort key combination. By breaking large collections or documents into individual child rows, each row remains well under the 400 KB limit while remaining queryable via the partition key.
