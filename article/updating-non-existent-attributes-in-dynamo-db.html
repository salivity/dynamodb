Updating Non-Existent Attributes in DynamoDB

When you execute an update operation on an Amazon DynamoDB attribute that does not exist, the database handles it dynamically rather than throwing a standard missing-field error. In most scenarios, DynamoDB either initializes the attribute automatically or treats the operation as a safe no-op (no operation). The exact outcome depends on the update action defined in your UpdateExpression—such as SET, ADD, REMOVE, or DELETE—as well as whether you are targeting top-level attributes, nested document paths, or utilizing condition expressions.

The SET Action

If you use the SET action on an attribute that does not exist on the item, DynamoDB automatically creates the attribute and assigns the specified value to it.

Furthermore, if the entire item itself does not exist in the table, DynamoDB performs an "upsert." It creates a brand-new item containing the primary key along with the newly defined attribute.

The ADD Action

The ADD action is supported only for numeric values and set data types:

  • Numbers: If the numeric attribute does not exist, DynamoDB assumes an initial value of 0 and then adds your specified value to it.
  • Sets: If the target set does not exist, DynamoDB creates a new set containing the elements you provided.

The REMOVE Action

If you attempt to REMOVE an attribute that does not exist, DynamoDB simply ignores the operation. No modification is made to the item, and no error or exception is returned.

The DELETE Action

The DELETE action is used specifically to remove elements from a set. If the set attribute itself does not exist, or if the specified elements are not present within the existing set, DynamoDB safely ignores the request without throwing an error.

Nested Document Paths and Validation Exceptions

While DynamoDB automatically creates missing top-level attributes, nested attributes inside maps and lists behave differently:

  • Parent Exists: If a parent map already exists on the item and you update a non-existent child attribute using a path like SET Address.PostalCode = :val, DynamoDB adds PostalCode to the Address map.
  • Parent Does Not Exist: If the parent map (Address) does not exist on the item, attempting to set a nested field directly will cause the request to fail with a ValidationException: The document path provided in the update expression is invalid for update. To update nested attributes safely when parent structures may be absent, you must ensure parent maps are initialized first.

Impact of Condition Expressions

If your update request includes a ConditionExpression, default creation behavior can be altered:

  • Using attribute_exists(attribute_name) will cause the entire update to fail with a ConditionalCheckFailedException if the attribute is absent.
  • Conversely, using attribute_not_exists(attribute_name) ensures the update only proceeds if the attribute is currently missing.
