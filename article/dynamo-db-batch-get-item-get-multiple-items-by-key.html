DynamoDB BatchGetItem: Get Multiple Items by Key

In Amazon DynamoDB, the API call used to retrieve multiple specific items using their primary keys in a single request is BatchGetItem. This operation allows applications to fetch up to 100 items across one or more tables efficiently, reducing network overhead compared to executing individual GetItem requests. This guide covers how BatchGetItem works, its limits, read consistency options, and how to handle partial failures.

How BatchGetItem Works

The BatchGetItem operation accepts a list of primary keys (partition keys, or partition and sort keys depending on the table schema) and returns the corresponding items. It executes these retrievals in parallel within DynamoDB.

Unlike queries or scans, BatchGetItem cannot filter by non-key attributes or search ranges without knowing the exact primary keys beforehand. Every requested item must be identified by its full primary key.

Multi-Table Retrieval

A single BatchGetItem request can retrieve items from multiple tables at once. You define the table name and the list of keys corresponding to each table within the RequestItems parameter of the payload.

{
  "RequestItems": {
    "Users": {
      "Keys": [
        {"UserId": {"S": "user_1"}},
        {"UserId": {"S": "user_2"}}
      ]
    },
    "Orders": {
      "Keys": [
        {"OrderId": {"S": "order_100"}}
      ]
    }
  }
}

Core Constraints and Limitations

When utilizing BatchGetItem, several operational limits apply:

  • Item Count Limit: A single request can retrieve a maximum of 100 items.
  • Payload Size Limit: The maximum total response size is 16 MB. If the data exceeds 16 MB, DynamoDB returns the items up to the limit along with unprocessed keys.
  • Primary Key Requirement: You must supply the complete primary key for each requested item.

Read Consistency Options

By default, BatchGetItem performs eventually consistent reads. However, you can configure strongly consistent reads on a per-table basis within the request by setting ConsistentRead to true. Strongly consistent reads consume twice as many read capacity units (RCUs) as eventually consistent reads.

Handling Unprocessed Keys

A BatchGetItem request can partially succeed. If throughput capacity is exceeded or if the response reaches the 16 MB threshold, DynamoDB returns a 200 OK response containing both:

  1. Responses: The items successfully fetched.
  2. UnprocessedKeys: The list of keys that were not retrieved.

Applications must inspect the UnprocessedKeys field in the response. If this field is not empty, the remaining keys should be submitted in a subsequent BatchGetItem call, typically using an exponential backoff algorithm to prevent throttling.
