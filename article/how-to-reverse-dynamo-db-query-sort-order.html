How to Reverse DynamoDB Query Sort Order

Amazon DynamoDB retrieves items in ascending order by default based on the table or index sort key. This article covers how to invert that default behavior using the dedicated query parameter, explains how it functions under the hood, and highlights key considerations regarding pagination and result limits.

The ScanIndexForward Parameter

In Amazon DynamoDB, the parameter used to reverse the search order along the sort key is ScanIndexForward.

ScanIndexForward is a boolean parameter available exclusively in Query operations:

  • true (Default): DynamoDB reads items in ascending order based on the sort key (e.g., 0 to 9, A to Z, or oldest to newest timestamps).
  • false: DynamoDB reads items in descending order based on the sort key (e.g., 9 to 0, Z to A, or newest to oldest timestamps).

How It Works

A Query operation requires an exact match on a partition key and allows sorting and filtering based on the sort key. When ScanIndexForward is set to false, DynamoDB starts traversing the partition from the highest sort key value and moves downward toward the lowest value.

This behavior applies equally to queries executed against the base table, Local Secondary Indexes (LSIs), and Global Secondary Indexes (GSIs).

Usage Example

In the AWS SDK (such as the AWS SDK for JavaScript/Node.js or Python/Boto3), the parameter is passed directly into the query input object:

{
  "TableName": "UserOrders",
  "KeyConditionExpression": "UserId = :uid",
  "ExpressionAttributeValues": {
    ":uid": { "S": "user_123" }
  },
  "ScanIndexForward": false
}

Impact on Pagination and the Limit Parameter

Setting ScanIndexForward to false directly impacts how DynamoDB applies the Limit parameter:

  1. Top-N Results: If you specify a Limit of 5 and set ScanIndexForward to false, DynamoDB returns the 5 items with the highest sort key values within that partition. This makes it an ideal pattern for retrieving the "most recent" records.
  2. Pagination: When using pagination with ExclusiveStartKey, the query will continue scanning in descending order from the specified starting key rather than moving forward.
