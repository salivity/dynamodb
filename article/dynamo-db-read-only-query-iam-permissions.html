DynamoDB Read-Only Query IAM Permissions

This guide explains how to configure AWS Identity and Access Management (IAM) to grant read-only query access to an Amazon DynamoDB table. It identifies the exact IAM action required for querying, provides a minimal JSON policy example, and covers essential scope considerations such as granting access to secondary indexes.

The Required IAM Action: dynamodb:Query

To grant permissions to query items in a DynamoDB table, the specific IAM action is dynamodb:Query.

This action permits users or roles to perform the Query API operation, retrieving items based on primary key values without granting broad read permissions across the entire database or allowing modifications.

Example IAM Policy for Read-Only Query Access

The following policy demonstrates the least-privilege approach to granting query permissions on a specific table and its indexes:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowDynamoDBQueryOnly",
      "Effect": "Allow",
      "Action": [
        "dynamodb:Query"
      ],
      "Resource": [
        "arn:aws:dynamodb:region:account-id:table/TableName",
        "arn:aws:dynamodb:region:account-id:table/TableName/index/*"
      ]
    }
  ]
}

Key Considerations

  • Secondary Indexes: If your query targets a Global Secondary Index (GSI) or Local Secondary Index (LSI), the policy must include permissions for the index ARN in addition to the base table ARN (as shown in the example resource list using table/TableName/index/*).
  • Query vs. Scan vs. GetItem:
    • dynamodb:Query: Reads items based on a partition key and optional sort key condition.
    • dynamodb:GetItem: Retrieves a single item by its complete primary key.
    • dynamodb:Scan: Reads every item in the table or secondary index.
  • AWS Managed Policies: If broader read-only access is acceptable, the AWS-managed policy AmazonDynamoDBReadOnlyAccess includes dynamodb:Query alongside actions like dynamodb:GetItem, dynamodb:BatchGetItem, and dynamodb:Scan.
