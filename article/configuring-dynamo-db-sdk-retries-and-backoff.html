Configuring DynamoDB SDK Retries and Backoff

Amazon DynamoDB automatically throttles requests that exceed provisioned throughput or partition limits, requiring client applications to handle retries gracefully. This article explains the specific AWS SDK parameters used to configure maximum retries and exponential backoff for DynamoDB requests across modern SDK implementations, detailing how these settings work under standard and adaptive retry modes.

The Core Configuration Parameter: maxAttempts

In modern AWS SDKs, the primary parameter used to configure the maximum number of retry attempts is maxAttempts (or max_attempts in Python).

AWS SDKs use built-in exponential backoff and jitter algorithms by default whenever retries are enabled. Because the backoff formula is inherently managed by the SDK's retry strategy, configuring retries does not require manually setting delay multipliers. Instead, defining the maximum attempt threshold dictates how many total attempts (the initial request plus subsequent retries) the client will make before raising an exception.

AWS SDK for Python (Boto3)

In Boto3, retries and backoff are configured using the Config object from botocore.config. The parameter is defined within a retries dictionary:

import boto3
from botocore.config import Config

config = Config(
    retries={
        'max_attempts': 5,
        'mode': 'standard'
    }
)

dynamodb = boto3.client('dynamodb', config=config)
  • max_attempts: An integer representing the total number of request attempts allowed (e.g., a value of 5 allows 1 initial request and up to 4 retries).
  • mode: The retry algorithm. Setting this to 'standard' implements exponential backoff with full jitter, while 'adaptive' dynamically manages request rates based on client-side rate limiting.

AWS SDK for JavaScript/TypeScript (v3)

In AWS SDK for JavaScript v3, the parameter is maxAttempts, passed directly into the client configuration object:

import { DynamoDBClient } from "@aws-sdk/client-dynamodb";

const client = new DynamoDBClient({
  maxAttempts: 5,
  retryMode: "standard"
});
  • maxAttempts: Specifies the maximum number of attempts the client will make for a single operation.
  • retryMode: Defines the backoff behavior ("standard" or "adaptive"). The standard mode applies exponential backoff with full jitter automatically.

AWS SDK for Java 2.x

In the Java SDK v2, retry behavior is configured using the ClientOverrideConfiguration and the RetryStrategy builder:

DynamoDbClient client = DynamoDbClient.builder()
    .overrideConfiguration(ClientOverrideConfiguration.builder()
        .retryStrategy(RetryMode.STANDARD)
        .build())
    .build();

To explicitly customize the retry limit, use RetryPolicy:

ClientOverrideConfiguration configuration = ClientOverrideConfiguration.builder()
    .retryPolicy(RetryPolicy.builder()
        .numRetries(5)
        .build())
    .build();

DynamoDbClient client = DynamoDbClient.builder()
    .overrideConfiguration(configuration)
    .build();
  • numRetries (or maxAttempts via the retry strategy builder): Sets the maximum number of retry attempts.

How Exponential Backoff Operates

When maxAttempts is configured with the standard retry mode:

  1. Failure Detection: The client identifies retryable errors, such as ProvisionedThroughputExceededException, RequestLimitExceeded, or transient HTTP 5xx errors.
  2. Exponential Backoff: The SDK calculates the sleep duration based on the formula:
    Wait Time = Base Delay * 2 ^ (Current Attempt)
  3. Full Jitter: A randomized jitter is applied to prevent the "thundering herd" problem, spreading out concurrent retries evenly over time.
  4. Termination: If the operation fails after reaching the specified maxAttempts, the SDK stops retrying and propagates the error to the calling application.
