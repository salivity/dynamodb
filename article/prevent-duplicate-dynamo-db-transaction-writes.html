Prevent Duplicate DynamoDB Transaction Writes

When executing transactional writes in Amazon DynamoDB, network blips or client-side timeouts can cause retries that risk processing the same operation more than once. This article explains the core mechanism DynamoDB uses to prevent duplicate executions—the Client Request Token—detailing how it guarantees idempotency, its behavioral lifecycle, and how to handle parameter mismatches during retries.

The Idempotency Mechanism: ClientRequestToken

DynamoDB prevents duplicate execution of transactional writes through idempotency, implemented via the ClientRequestToken parameter. When invoking the TransactWriteItems API, you can supply a unique, client-generated string token with the request.

By including a ClientRequestToken, you inform DynamoDB that the request can be retried safely. If DynamoDB receives a transaction request with a token it has already processed, it recognizes the operation as a duplicate and does not execute the transactional modifications a second time.

How the Token Works

  1. Initial Execution: The client generates a unique token (typically a Version 4 UUID) and sends it with the TransactWriteItems call. DynamoDB executes the write operations atomically across the targeted items and records the token.
  2. Safe Retries: If the connection drops or the client times out before receiving a response, the client can resend the exact same TransactWriteItems request with the identical ClientRequestToken.
  3. Response Matching: Instead of reapplying the writes, DynamoDB acknowledges that the transaction was already applied and returns the original success response.

Token Validity Window

A ClientRequestToken is valid for 10 minutes after the initial transaction request completes.

  • If a retry occurs within this 10-minute window with the same token, DynamoDB guarantees idempotent behavior.
  • If a request with the same token is submitted after the 10-minute window has expired, DynamoDB treats it as a brand-new transaction and executes the writes again.

Handling IdempotentParameterMismatchException

DynamoDB validates that all request parameters match when reusing a ClientRequestToken. If a client sends a request with a previously used token but changes any part of the transaction payload—such as item keys, attributes, or conditions—DynamoDB rejects the call and throws an IdempotentParameterMismatchException.

To avoid this error, ensure that retries only reuse the token if the entire payload of the TransactWriteItems request is identical to the original call.
