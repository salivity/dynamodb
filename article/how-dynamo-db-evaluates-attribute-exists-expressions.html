How DynamoDB Evaluates attribute_exists Expressions

Amazon DynamoDB uses the attribute_exists function within condition and filter expressions to determine whether a target attribute is present in an item. This article explains how DynamoDB parses and evaluates this function, how it navigates nested document paths, how it handles explicit NULL values versus missing attributes, and how its boolean result dictates whether write operations succeed or read items are returned.

Syntax and Basic Evaluation

The attribute_exists function accepts a single argument: the path to the attribute being checked.

attribute_exists(path)

During evaluation, DynamoDB inspects the item currently being processed and returns a boolean value:

  • TRUE: If the specified attribute path exists on the item.
  • FALSE: If the attribute does not exist on the item.

Contexts of Evaluation

DynamoDB evaluates attribute_exists during two primary workflows:

  1. Conditional Writes (ConditionExpression): Used in PutItem, UpdateItem, and DeleteItem requests. DynamoDB retrieves the existing item from storage before applying the write. It evaluates the expression against the current state of the item. If attribute_exists evaluates to FALSE (and is not negated), the entire write fails, and DynamoDB raises a ConditionalCheckFailedException.
  2. Read Filtering (FilterExpression): Used in Query and Scan operations. DynamoDB reads the item from storage first, evaluates attribute_exists, and only includes the item in the returned result set if the expression evaluates to TRUE. Filter expressions do not reduce read capacity consumption, as evaluation occurs after the item is read.

Nested Paths and Document Traversal

The path parameter supports complex document paths, allowing evaluation inside DynamoDB Maps and Lists:

  • Maps: To check for a nested key, use dot notation (e.g., attribute_exists(Address.ZipCode)). DynamoDB evaluates the hierarchy from left to right. If any intermediate parent attribute does not exist, the evaluation safely yields FALSE without throwing an error.
  • Lists: To check for an element at a specific index, use bracket notation (e.g., attribute_exists(PhoneNumbers[0])). If the list has fewer elements than the specified index, the expression evaluates to FALSE.

Attribute Existence vs. The NULL Data Type

A common misconception involves attributes stored with the DynamoDB NULL data type ({"NULL": true}).

In DynamoDB, an attribute explicitly set to NULL is still an existing attribute. Therefore:

  • attribute_exists(my_attribute) evaluates to TRUE if my_attribute contains the value NULL.
  • It evaluates to FALSE only if the attribute key is completely absent from the item.

Combining with Logical Operators

The boolean result of attribute_exists can be chained using DynamoDB's logical operators: AND, OR, and NOT.

  • Negation: While DynamoDB provides a dedicated attribute_not_exists(path) function, wrapping NOT attribute_exists(path) produces an identical boolean outcome.
  • Compound Logic: You can combine existence checks with value comparisons. For example, attribute_exists(user_id) AND age > :min_age requires the user_id attribute to be present and the age attribute to both exist and exceed the specified threshold. DynamoDB uses short-circuit evaluation for logical operations where applicable.
