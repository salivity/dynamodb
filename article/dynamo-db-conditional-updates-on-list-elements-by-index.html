DynamoDB Conditional Updates on List Elements by Index

Amazon DynamoDB supports updating specific elements within a list attribute using zero-based index notation in conjunction with conditional expressions. By utilizing document paths such as attribute[index] within both the UpdateExpression and ConditionExpression, you can target precise positions in a list while ensuring modifications occur only if the element meets predefined criteria. This article explains how DynamoDB processes these index-based conditional updates, the mechanics of evaluation, syntax examples, and critical edge cases to consider.

The Mechanics of Index-Based Targeting

DynamoDB lists are ordered collections of DynamoDB-type values. You access individual elements using bracketed zero-based integer notation (e.g., Tasks[0], Tasks[1]).

When executing a conditional update on a specific list element, you combine two primary clauses:

  1. ConditionExpression: Evaluates whether the element at a specific index exists or contains a specific value before applying the update.
  2. UpdateExpression: Specifies the modification to apply using the SET or REMOVE action at that specific index path.

Both expressions evaluate against the existing state of the item in the database before any writes are applied.

Syntax and Implementation Example

To safely update a list element by its index, the request must target the exact path in both expressions.

{
  "TableName": "ProjectManagement",
  "Key": {
    "ProjectId": {"S": "p-100"}
  },
  "UpdateExpression": "SET TeamMembers[2] = :new_member",
  "ConditionExpression": "TeamMembers[2] = :expected_member",
  "ExpressionAttributeValues": {
    ":new_member": {"S": "Alice"},
    ":expected_member": {"S": "Bob"}
  }
}

In this operation:

  • DynamoDB inspects index 2 of the TeamMembers list.
  • If the value at index 2 is equal to "Bob", DynamoDB replaces it with "Alice".
  • If the value at index 2 is not "Bob", or if index 2 does not exist, the operation aborts and throws a ConditionalCheckFailedException.

How DynamoDB Evaluates Conditions on List Indices

During execution, DynamoDB handles the conditional check atomically:

  • Checking Value Equality: If the condition specifies ListAttr[i] = :val, DynamoDB checks if index i exists and equals :val. If the index is out of bounds, the condition evaluates to false.
  • Checking Existence: You can use attribute_exists(ListAttr[i]) to verify that the list contains at least i + 1 elements before updating, preventing unintended appends or errors.
  • Type Safety: If ListAttr is not actually a List (for example, if it is a String or Map), DynamoDB returns a ValidationException.

Important Limitations and Edge Cases

1. Index Shifting and Concurrency

DynamoDB does not track the identity of elements; it tracks only the array index. If concurrent writes remove (REMOVE ListAttr[0]) or prepend items to the list, the indices of subsequent elements shift immediately. Consequently, an operation targeting index 2 might accidentally evaluate and update the wrong logical element unless the ConditionExpression explicitly checks the element's unique value or identifier.

2. Out-of-Bounds Restrictions

You cannot use SET to write to an index that is strictly greater than the current size of the list. For example, if a list contains 3 items (indices 0, 1, 2), attempting to update ListAttr[4] will fail with a ValidationException. You can only append to the immediate end of the list using ListAttr[3].

3. List Element Deletion

Using REMOVE ListAttr[i] conditionally will delete the element at index i and immediately collapse the list, shifting all higher-indexed elements down by one position. If a condition check fails, the list remains unchanged.
