DynamoDB Capacity for Null Attribute Values

When designing schemas in Amazon DynamoDB, understanding how different data types impact capacity unit consumption is critical for cost optimization and performance. In DynamoDB, attributes containing a NULL data type are not free; they contribute to the total item size by counting both the byte length of the attribute name and a fixed one-byte overhead for the null value itself. Consequently, these bytes add to the total item size, directly influencing the calculation of Write Capacity Units (WCU) and Read Capacity Units (RCU) whenever the item is written or read.

DynamoDB Item Size Calculation Formula

DynamoDB determines the size of an item by adding the length of all attribute names (in UTF-8 bytes) to the length of their respective attribute values.

For an attribute explicitly set to the NULL type:

  • Attribute Name: Length in bytes of the attribute name encoded in UTF-8.
  • Attribute Value: Exactly 1 byte.

For example, an attribute named "status" with a value of NULL consumes:

  • 6 bytes for the name ("status")
  • 1 byte for the NULL value
  • Total size contribution: 7 bytes

Impact on Write Capacity Units (WCU)

Write capacity calculations are based on total item size rounded up to the nearest 1 KB chunk:

  • Standard Writes: 1 WCU per 1 KB of data written.
  • Transactional Writes: 2 WCUs per 1 KB of data written.

Because a null attribute adds to the aggregate item size, it can push an item over a 1 KB boundary. For example, if an item without null attributes measures 1,020 bytes, it consumes 1 WCU. If adding a null attribute increases the item size to 1,027 bytes, the required capacity rounds up to the next 1 KB increment, consuming 2 WCUs.

Impact on Read Capacity Units (RCU)

Read operations round the total item size up to the nearest 4 KB chunk:

  • Strongly Consistent Reads: 1 RCU per 4 KB read.
  • Eventually Consistent Reads: 0.5 RCU per 4 KB read.
  • Transactional Reads: 2 RCUs per 4 KB read.

Just as with writes, if null attributes increase the total byte size beyond a 4 KB boundary (e.g., from 4,090 bytes to 4,098 bytes), the read capacity consumption doubles to account for the next 4 KB increment.

Storing Null vs. Omitting Attributes

DynamoDB is a schemaless, NoSQL database. You are not required to store attributes with a NULL value to represent absent data.

  • Storing NULL: Consumes the byte length of the attribute name plus 1 byte for the value.
  • Omitting the Attribute (Sparse Data): Consumes 0 bytes.

Omitting attributes rather than explicitly setting them to NULL reduces item size, lowers storage costs, and minimizes the risk of crossing capacity boundaries that trigger additional WCU and RCU consumption.
