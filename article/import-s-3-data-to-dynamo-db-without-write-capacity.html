Import S3 Data to DynamoDB Without Write Capacity

Amazon DynamoDB's native Import from Amazon S3 feature allows you to ingest massive datasets directly into new DynamoDB tables without consuming any write capacity units (WCUs). This article covers how this serverless feature works, its primary benefits, supported data formats, and how it eliminates the overhead of managing provisioned throughput or custom ETL pipelines during large-scale data migrations.

What Is DynamoDB Import from Amazon S3?

DynamoDB Import from Amazon S3 is a fully managed feature designed to load gigabytes or terabytes of data directly from an Amazon S3 bucket into a brand-new DynamoDB table. Because it is handled internally by DynamoDB's backend infrastructure, it does not use your table's write capacity, making it both cost-effective and significantly faster than traditional write-based ingestion methods.

Why It Eliminates Write Capacity Consumption

Under traditional import methods (such as using AWS Lambda, Amazon EMR, or custom scripts), every record written to DynamoDB issues a PutItem or BatchWriteItem API request. These requests consume provisioned Write Capacity Units (WCUs) or On-Demand write request units, requiring you to either over-provision your table—incurring high costs—or throttle your application's regular traffic.

The S3 import feature bypasses the standard write API pipeline entirely:

  • No WCU/RRU Consumption: The import does not count against your read/write throughput quotas or your billing for capacity units.
  • Independent Resource Allocation: DynamoDB allocates dedicated backend compute and storage resources to build the table files directly.
  • Isolated Performance: Because the import targets a new table, existing production workloads in your AWS account remain completely unaffected.

Supported Formats and Compression

The import feature supports widely used file formats and compression types, minimizing the preparation required before loading data:

  • Data Formats:
    • CSV: Standard comma-separated values with customizable delimiters.
    • DynamoDB JSON: Standard DynamoDB attribute value format containing explicit data types (e.g., {"S": "value"}).
    • Amazon Ion: A rich-type superset of JSON developed by Amazon.
  • Compression:
    • GZIP (.gz)
    • ZSTD (.zst)
    • Uncompressed

Key Benefits

  • Lower Cost: You pay only for the uncompressed size of the source data imported and standard S3 storage costs, which is significantly cheaper than provisioning millions of WCUs for high-throughput batch writes.
  • No Infrastructure Overhead: Eliminates the need to provision, configure, and monitor intermediate compute resources like AWS Glue, EC2 instances, or Lambda functions.
  • Secondary Index Creation: You can define Global Secondary Indexes (GSIs) and Local Secondary Indexes (LSIs) as part of the import configuration; the indexes are populated concurrently during the import process without consuming write capacity.

How the Import Process Works

  1. Stage Data in S3: Place your source files in an Amazon S3 bucket within the same AWS Region as your target DynamoDB table.
  2. Initiate the Import: Start the import job via the AWS Management Console, AWS CLI, or AWS SDK by providing the source S3 URL, file format, and compression type.
  3. Define Table Configuration: Specify the target table name, primary key (partition key and optional sort key), secondary indexes, and billing mode (Provisioned or On-Demand).
  4. Automated Processing: DynamoDB validates the source data, provisions the new table, parses the files, and populates the data alongside any configured secondary indexes.
  5. Review CloudWatch Metrics: CloudWatch tracks the status, detailing processed records, errors, and validation failures directly through the DynamoDB console.
