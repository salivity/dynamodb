How DynamoDB Supports Native JSON in API Requests

Amazon DynamoDB provides native support for JSON document structures, allowing developers to store, query, and manipulate complex, hierarchical data directly through its API. This article explains how DynamoDB maps JSON to native data types, how AWS SDKs simplify JSON handling through document clients, and how to read and modify nested attributes efficiently using expressions.

Native Document Data Types: Maps and Lists

DynamoDB supports JSON natively by offering two document data types alongside its scalar types:

  • Map (M): Represents an unordered collection of name-value pairs, directly mirroring a JSON object. Maps can store nested elements of any data type, including other maps and lists.
  • List (L): Represents an ordered collection of values, directly mirroring a JSON array. Lists can contain heterogeneous data types within the same array.

When interacting with the low-level DynamoDB API, JSON structures are explicitly typed. For example, a JSON object containing a user profile is transmitted with explicit type descriptors:

{
  "Item": {
    "UserId": {"S": "12345"},
    "Profile": {
      "M": {
        "Name": {"S": "Jane Doe"},
        "Preferences": {
          "M": {
            "Theme": {"S": "Dark"},
            "Notifications": {"BOOL": true}
          }
        },
        "Tags": {
          "L": [
            {"S": "admin"},
            {"S": "developer"}
          ]
        }
      }
    }
  }
}

Automatic Serialization with SDK Document Clients

Writing explicit type descriptors manually is cumbersome. To streamline integration, AWS SDKs provide a high-level Document Client abstraction.

The Document Client automatically serializes standard JSON objects into DynamoDB's low-level attribute format upon request and deserializes responses back into native language objects (such as JavaScript objects or Python dictionaries).

When using a Document Client, native JSON payloads can be passed directly into API calls such as PutItem, GetItem, and UpdateItem:

// Example using AWS SDK for JavaScript v3 DynamoDBDocumentClient
const params = {
  TableName: "Users",
  Item: {
    UserId: "12345",
    Profile: {
      Name: "Jane Doe",
      Preferences: {
        Theme: "Dark",
        Notifications: true
      },
      Tags: ["admin", "developer"]
    }
  }
};

await docClient.send(new PutCommand(params));

Accessing Nested Data with Document Paths

DynamoDB allows granular access to nested JSON attributes using document paths in expression parameters. This eliminates the need to rewrite or retrieve an entire document when interacting with a specific nested key.

  • Dot Notation (.): Navigates through elements in a Map (e.g., Profile.Preferences.Theme).
  • Bracket Notation ([]): Navigates through elements in a List using a zero-based index (e.g., Profile.Tags[0]).

Targeted Updates and Retrievals

By combining document paths with DynamoDB expressions, API requests can execute precise operations on JSON documents:

  • UpdateExpression: Allows adding, updating, or removing individual keys inside a nested structure without replacing the whole parent document:

    SET Profile.Preferences.Theme = :newTheme, Profile.Tags[1] = :newTag

  • ProjectionExpression: Restricts returned data to specific nested fields, reducing network payload size:

    Profile.Name, Profile.Preferences.Notifications

  • ConditionExpression: Validates conditions against nested properties before executing writes:

    attribute_exists(Profile.Preferences) AND Profile.Preferences.Notifications = :status

Through these native data types and path expressions, DynamoDB treats JSON not merely as raw text strings, but as fully queryable, structured records natively supported across all standard API operations.
