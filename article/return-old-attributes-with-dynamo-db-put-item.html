Return Old Attributes with DynamoDB PutItem

When replacing or inserting an item using Amazon DynamoDB's PutItem API, you can capture the item's previous state by configuring the ReturnValues parameter. By setting this parameter to ALL_OLD, DynamoDB returns all the attributes of the item as they existed prior to the PutItem operation. This article explains how the ReturnValues parameter works in a PutItem call, the supported values, and key considerations when using it.

The ReturnValues Parameter

In DynamoDB, the parameter responsible for determining what the operation returns is ReturnValues.

While operations like UpdateItem support multiple return configurations (such as UPDATED_OLD, ALL_NEW, and UPDATED_NEW), the PutItem operation only supports two values:

  • NONE (Default): DynamoDB returns nothing in the response regarding the item's prior state.
  • ALL_OLD: DynamoDB returns the complete item with all its attributes exactly as they appeared before the PutItem request overwrote it.

How ALL_OLD Works in Practice

When a PutItem request includes ReturnValues="ALL_OLD":

  1. Item Exists: If an item with the matching partition key (and sort key, if applicable) already exists in the table, the response payload will include an Attributes map containing the entire previous item.
  2. Item Does Not Exist: If no matching item exists prior to the call, the PutItem operation succeeds, but the Attributes field in the response remains empty.

Example (AWS SDK for Python / Boto3)

import boto3

dynamodb = boto3.client('dynamodb')

response = dynamodb.put_item(
    TableName='Users',
    Item={
        'UserId': {'S': 'user_123'},
        'Email': {'S': 'new_email@example.com'},
        'Status': {'S': 'Active'}
    },
    ReturnValues='ALL_OLD'
)

# Access the attributes prior to the update
old_item = response.get('Attributes')

Consumed Capacity Implications

Requesting previous attributes with ReturnValues='ALL_OLD' on a PutItem call requires DynamoDB to perform a read operation before writing the new item. As a result, the operation consumes both write capacity units (WCUs) for storing the new item and read capacity units (RCUs) for fetching the existing item attributes.
