DynamoDB Object Persistence Model in .NET

The AWS SDK for .NET provides the DynamoDB Object Persistence Model as its primary feature for client-side object mapping. This article explains how the Object Persistence Model works, highlights its core components such as DynamoDBContext, reviews essential mapping attributes, and demonstrates how it streamlines read and write operations by directly converting C# classes into Amazon DynamoDB items without manual attribute mapping.

What is the Object Persistence Model?

The Object Persistence Model is a high-level abstraction layer within the AWSSDK.DynamoDBv2 NuGet package. Unlike the low-level service model, which requires interacting with raw dictionaries of AttributeValue objects, or the Document Model, which deals with loosely typed Document primitives, the Object Persistence Model allows developers to map client-side .NET classes directly to DynamoDB tables.

Core Component: DynamoDBContext

The central entry point of the Object Persistence Model is the DynamoDBContext class. It manages the connection to DynamoDB and handles the serialization of .NET objects into DynamoDB attributes, as well as the deserialization of DynamoDB responses back into strongly typed C# objects.

To use DynamoDBContext, instantiate it with an IAmazonDynamoDB client instance:

using Amazon.DynamoDBv2;
using Amazon.DynamoDBv2.DataModel;

IAmazonDynamoDB client = new AmazonDynamoDBClient();
DynamoDBContext context = new DynamoDBContext(client);

Mapping Attributes

The model uses declarative attributes from the Amazon.DynamoDBv2.DataModel namespace to define how C# class properties map to DynamoDB table schemas:

  • [DynamoDBTable("TableName")]: Specifies the target DynamoDB table name for the class.
  • [DynamoDBHashKey]: Designates the property as the partition key (hash key).
  • [DynamoDBRangeKey]: Designates the property as the sort key (range key), if one exists.
  • [DynamoDBProperty]: Maps a property to a specific attribute name in the table or configures custom converters.
  • [DynamoDBIgnore]: Instructs the context to ignore the property during serialization and deserialization.
  • [DynamoDBVersion]: Enables optimistic locking by managing a version number attribute automatically.

Example Model Definition

[DynamoDBTable("Users")]
public class User
{
    [DynamoDBHashKey]
    public string UserId { get; set; }

    [DynamoDBProperty]
    public string Email { get; set; }

    [DynamoDBProperty("CreatedAtUtc")]
    public DateTime CreatedAt { get; set; }

    [DynamoDBIgnore]
    public string InternalNotes { get; set; }
}

Performing CRUD Operations

DynamoDBContext provides straightforward asynchronous methods to interact with tables:

  • Save: await context.SaveAsync(user); creates or updates an item.
  • Load: User user = await context.LoadAsync<User>(userId); retrieves an item by its primary key.
  • Delete: await context.DeleteAsync<User>(userId); removes an item by its key.
  • Query and Scan: context.QueryAsync<User>(partitionKey) and context.ScanAsync<User>(conditions) return strongly typed collections based on query conditions or full table scans.

Advantages

  • Type Safety: Eliminates string-based attribute access, reducing runtime errors.
  • Reduced Boilerplate: Removes the need to manually construct AttributeValue dictionaries.
  • Built-in Optimistic Locking: Simplifies concurrency management using the [DynamoDBVersion] attribute.
  • Custom Converters: Supports complex types via IPropertyConverter for custom serialization logic.
