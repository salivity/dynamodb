DynamoDB Change Data Capture with Kinesis Streams

Amazon DynamoDB captures item-level modifications—inserts, updates, and deletes—in real time and streams them directly to Amazon Kinesis Data Streams without custom code or provisioning additional compute. This native Change Data Capture (CDC) integration enables architectures to ingest database mutation events into a centralized streaming pipeline for real-time analytics, multi-region replication, audit logging, and downstream event-driven processing. It provides high-throughput event streaming with flexible retention periods, decoupling change ingestion from the core operational database workload.

How the Integration Works

When enabled on a DynamoDB table, the Kinesis Data Streams integration monitors the database's internal transaction logs. Whenever an application writes, updates, or deletes an item in the DynamoDB table, an event record is asynchronously extracted and written to the designated Kinesis data stream.

Because this extraction process occurs out-of-band, streaming records does not consume read capacity units (RCUs) or write capacity units (WCUs) from the source DynamoDB table. The performance and latency of write operations on DynamoDB remain unaffected.

Record Structure and Information

Each event published to Kinesis contains detailed metadata and payload attributes about the modification:

  • Event Name: Identifies the type of operation performed (INSERT, MODIFY, or REMOVE).
  • Keys: The partition key and sort key of the modified item.
  • Item Images: Depending on how the mutation occurred, the payload includes the item's previous state (OldImage), the new state after modification (NewImage), or both.
  • Approximate Creation DateTime: A timestamp indicating when the item modification was recorded in DynamoDB.

Ordering and Shard Distribution

DynamoDB uses the primary key of the modified item as the partition key when routing records to Kinesis Data Streams. Because Kinesis routes records to specific shards based on hash key mapping, all sequential modifications to a single DynamoDB item are directed to the same shard. This guarantees strict chronological ordering of change events for any specific item, allowing downstream consumers to reliably reconstruct state transitions.

Key Operational Advantages

Integrating DynamoDB CDC with Kinesis Data Streams introduces distinct functional capabilities compared to standard DynamoDB Streams:

  • Extended Data Retention: While standard DynamoDB Streams retain records for a strict 24-hour window, Kinesis Data Streams allows configurable retention from 24 hours up to 365 days, accommodating long replay windows and disaster recovery scenarios.
  • High-Throughput Fan-Out: With Kinesis Enhanced Fan-Out (EFO), multiple independent consumer applications can read from the stream simultaneously with dedicated read throughput (2 MB/second per shard per consumer) without contending for bandwidth.
  • Direct Ecosystem Integrations: Change events can be consumed natively by AWS Lambda, Amazon Managed Service for Apache Flink, or routed to storage sinks like Amazon S3, Amazon OpenSearch Service, and data warehouses via Amazon Data Firehose.
