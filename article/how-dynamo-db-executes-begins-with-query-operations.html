How DynamoDB Executes begins_with Query Operations

This article provides a comprehensive overview of how Amazon DynamoDB processes Query operations using the begins_with function. It covers the underlying architectural mechanics, including partition routing, sort key indexing, and contiguous sequential reads at the storage layer. Additionally, it highlights performance characteristics, read capacity unit (RCU) consumption, and data type constraints to provide a clear technical understanding of this operation.

The Role of the Primary Key in Queries

To understand how begins_with works, you must first understand DynamoDB's composite primary key structure, which consists of a Partition Key (PK) and a Sort Key (SK).

When executing a Query operation:

  • The Partition Key requires an exact equality condition (PK = :value).
  • The Sort Key allows range-based condition expressions, such as =, <, >, between, and begins_with.

The begins_with function cannot be used on a Partition Key; it is exclusively valid on the Sort Key within a Query operation's KeyConditionExpression (or within non-key attributes via a FilterExpression, though with vastly different performance implications).

Step-by-Step Execution Mechanics

When a Query request containing a begins_with key condition reaches DynamoDB, the system executes the request through several sequential steps:

1. Partition Routing

DynamoDB hashes the Partition Key value specified in the request using an internal hash function (MD5-based). This hash determines the exact physical storage partition where the matching data resides. Because an exact Partition Key is required, DynamoDB routes the query directly to the target partition replica group without inspecting any other partitions across the cluster.

2. Lexicographical Tree Navigation

Within the target physical partition, items that share the same Partition Key are stored in a sorted structure, typically a B-tree or a similar indexed data structure, ordered by the Sort Key.

For strings and binary data types, this ordering is strictly lexicographical by UTF-8 binary encoding. When begins_with(SK, :prefix) is evaluated, the storage engine does not scan all sort keys. Instead, it performs a binary search or tree traversal to locate the exact starting node—the first key that matches or is greater than or equal to the specified prefix.

3. Contiguous Range Scanning

Because all elements sharing a common prefix are stored adjacently in lexicographical order, the storage node performs a sequential read starting from the first matching entry.

The read operation moves forward sequentially through the storage blocks until it encounters the first Sort Key value that no longer starts with the provided prefix. At that exact boundary, reading halts immediately.

Performance and Read Capacity Consumption

Because begins_with leverages the physical ordering of the Sort Key, it is an efficient, targeted read operation rather than a brute-force scan.

  • Computational Complexity: Finding the starting point takes \(O(\log N)\) time, where \(N\) is the number of items under that Partition Key. Scanning the results takes \(O(K)\) time, where \(K\) is the number of items that match the prefix.
  • Read Capacity Units (RCUs): DynamoDB charges read capacity based on the aggregate size of all items read from the disk to satisfy the condition, rounded up to the nearest 4 KB. Because DynamoDB only reads the contiguous range of items matching the prefix, RCUs are consumed strictly by the matching items (plus any items traversed if an additional non-key FilterExpression is applied subsequently).

Data Type Constraints

The begins_with function is restricted at the API and storage engine levels to:

  • String (S)
  • Binary (B)

It cannot be executed on Number (N) sort keys because numbers in DynamoDB are ordered numerically, not character-by-character. Prefix-based evaluation does not align with numerical sorting semantics.

Key Takeaway

In a Query operation, begins_with acts as a high-performance range filter. By combining hash-based routing to an isolated partition with index traversal and contiguous disk reads, DynamoDB locates and retrieves prefix-matched items with predictable, single-digit millisecond latency regardless of the total table size.
