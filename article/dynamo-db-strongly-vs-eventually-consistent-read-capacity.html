DynamoDB Strongly vs Eventually Consistent Read Capacity

Amazon DynamoDB determines throughput costs based on consumed Read Capacity Units (RCUs), which are calculated using the size of the item read and the requested consistency model. This guide explains the exact formulas, 4 KB boundary rules, and calculations used to compute consumed read capacity for strongly consistent reads versus eventually consistent reads, helping you predict and optimize workload costs.

Read Capacity Unit (RCU) Fundamentals

A single Read Capacity Unit (RCU) represents:

  • One strongly consistent read per second for an item up to 4 KB in size.
  • Two eventually consistent reads per second for an item up to 4 KB in size.

Before applying the consistency multiplier, DynamoDB rounds the total size of the retrieved item up to the nearest 4 KB increment.

Calculation Rules by Consistency Model

Strongly Consistent Reads

A strongly consistent read returns a response that reflects all successful write operations that occurred prior to the read.

To compute consumed capacity:

  1. Divide the item size by 4 KB.
  2. Round up to the nearest integer.
  3. Multiply by 1 RCU.

Formula: Consumed RCUs = CEIL(Item Size in KB / 4 KB) * 1

Eventually Consistent Reads

An eventually consistent read maximizes read throughput at the lowest cost, though the response might not immediately reflect the results of a recently completed write request. DynamoDB provides a 50% discount on RCUs for this model.

To compute consumed capacity:

  1. Divide the item size by 4 KB.
  2. Round up to the nearest integer.
  3. Multiply by 0.5 RCU.

Formula: Consumed RCUs = CEIL(Item Size in KB / 4 KB) * 0.5

Batch and Multi-Item Reads

When performing batch operations such as BatchGetItem or queries returning multiple items:

  • GetItem and BatchGetItem: DynamoDB evaluates each item individually. An operation reading two 1.5 KB items strongly consistent consumes 2 RCUs (1 RCU per item), not 1 RCU for the combined 3 KB payload.
  • Query and Scan: DynamoDB sums the sizes of all items returned in the operation first, rounds the total sum up to the nearest 4 KB boundary, and then applies the consistency multiplier. Reading two 1.5 KB items via Query yields a 3 KB total, which rounds to 4 KB, consuming 1 RCU for strongly consistent or 0.5 RCU for eventually consistent reads.
