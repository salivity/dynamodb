How DynamoDB Global Tables Calculate WCUs

DynamoDB global tables use a multi-Region, multi-active replication model where write capacity is consumed both in the region where the write originates and in every replica region across the globe. When calculating Write Capacity Units (WCUs) across all regions, every local write requires standard WCUs in the origin region, plus an equivalent amount of Replicated Write Capacity Units (rWCUs) in each replica region. Consequently, the total write capacity consumed across your global footprint scales directly with the number of regions in your global table.

The Core Replication Rule

DynamoDB global tables replicate data asynchronously across all chosen regions. Because every replica table must maintain an identical state, every write operation performed in one region must be applied to all other replica regions.

The baseline formula for total write capacity across all regions is:

\[\text{Total Write Units Consumed} = \text{Local Write Units} + (\text{Local Write Units} \times (\text{Total Regions} - 1))\]

In simple terms: if you write an item in one region, you pay for one local write in that region, plus one replicated write in every other region.

Provisioned Capacity Mode

In provisioned capacity mode, writes are measured using standard WCUs and Replicated Write Capacity Units (rWCUs):

  • Local Writes: Consumed in the region handling the initial write request. One standard WCU provides one write per second for an item up to 1 KB in size.
  • Replicated Writes: Consumed in each secondary region during replication. One rWCU is required to replicate an item up to 1 KB in size to that specific region.
  • Pricing and Metrics: While rWCUs are metered separately on your bill, they consume capacity at a 1:1 ratio relative to standard WCUs for standard operations.

Example Calculation

If you have a global table with three regions (US East, US West, and Europe West) and write a 2 KB item to US East:

  • US East (Origin): Consumes 2 WCUs (2 KB / 1 KB per unit).
  • US West (Replica): Consumes 2 rWCUs.
  • Europe West (Replica): Consumes 2 rWCUs.
  • Total Capacity Across All Regions: 2 local WCUs + 4 rWCUs = 6 total capacity units.

To prevent replication lag and throttling, you must provision equal write capacity across all replica tables or configure DynamoDB auto scaling with identical target utilization settings across all regions.

On-Demand Capacity Mode

If your global table is set to on-demand capacity mode, capacity calculations follow the exact same structural ratio, but are metered as Write Request Units (WRUs) and Replicated Write Request Units (rWRUs):

  • A local write consumes 1 WRU per 1 KB.
  • Each replica region consumes 1 rWRU per 1 KB to apply the replicated update.
  • A single 1 KB write in a four-region global table will consume 1 WRU in the primary region and 3 rWRUs distributed across the remaining three regions.

How Item Size Affects Write Capacity

Replication capacity scales with the size of the item written, rounded up to the nearest 1 KB boundary:

  • Items \(\le\) 1 KB: Consumes 1 local write unit and 1 replicated write unit per replica region.
  • Items between 1 KB and 2 KB: Consumes 2 local write units and 2 replicated write units per replica region.
  • Items between \(N\) and \(N+1\) KB: Consumes \(N+1\) local units and \(N+1\) replicated units per replica region.

Update operations replicate the entire updated item, not just the modified attributes. Therefore, updating a single attribute on a 5 KB item consumes capacity based on the full 5 KB item size across all replica regions.

Transactional Writes

Transactional write operations (TransactWriteItems) double the local capacity consumption because DynamoDB performs two internal reads and writes to guarantee atomicity:

  • In the origin region: A 1 KB transactional write consumes 2 local WCUs.
  • In replica regions: Global tables do not replicate transactions atomically across regions; instead, updates are replicated eventually as standard idempotent single-item writes. Therefore, each replica region consumes only standard replicated capacity (1 rWCU for a 1 KB item), not transactional capacity.
