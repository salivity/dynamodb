DynamoDB BatchWriteItem Max Items Limit

This article covers the core operational limits and payload specifications for Amazon DynamoDB's BatchWriteItem API. It outlines the exact item count constraints, total payload size thresholds, supported operations, and key architectural considerations for handling large volumes of writes efficiently.

In Amazon DynamoDB, the maximum number of items that can be written or deleted in a single BatchWriteItem call is 25 items. This limit is a hard cap set by AWS and cannot be increased.

Key Constraints of BatchWriteItem

In addition to the 25-item limit per request, several other restrictions apply:

  • Maximum Request Size: The total payload size of all items in a single BatchWriteItem call cannot exceed 16 MB.
  • Individual Item Size: Individual items within the batch are subject to the standard DynamoDB limit of 400 KB each.
  • Allowed Operations: The batch operation only supports PutRequest (to insert or replace an item) and DeleteRequest (to remove an item). It does not support UpdateItem operations.

Handling More Than 25 Items

When your application needs to write more than 25 items, you must split your data into smaller chunks before making the API calls.

  1. Chunking: Partition your dataset into arrays containing 25 or fewer items.
  2. Execution: Execute multiple BatchWriteItem requests sequentially or in parallel depending on your provisioned or on-demand throughput capacity.

Managing Unprocessed Items

A BatchWriteItem call does not guarantee atomic "all-or-nothing" execution. DynamoDB can succeed in writing some items while failing on others, typically due to provisioned throughput exhaustion.

When this happens, DynamoDB returns an HTTP 200 status code alongside an UnprocessedItems object in the response. Your application logic must inspect this object and retry the unprocessed items, preferably using an exponential backoff algorithm to prevent repeated throttling.
