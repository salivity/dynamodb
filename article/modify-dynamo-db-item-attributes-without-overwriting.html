Modify DynamoDB Item Attributes Without Overwriting

In Amazon DynamoDB, modifying specific attributes of an existing item without overwriting the entire record is accomplished using the UpdateItem API operation. While standard operations like PutItem completely replace existing items, UpdateItem allows in-place modifications, saving bandwidth, reducing write capacity unit (WCU) consumption, and minimizing race conditions. This guide explains how the UpdateItem operation works, its syntax, and how to use update expressions for partial item modifications.

The UpdateItem Operation

The UpdateItem API edits an existing item's attributes or inserts a new item if the specified item does not already exist. Unlike PutItem—which replaces the entire target item—UpdateItem selectively updates, adds, or deletes individual attributes while leaving all unspecified attributes untouched.

How UpdateItem Modifies Data

To target and modify attributes precisely, UpdateItem uses several key parameters:

  • Key: Identifies the primary key (partition key and sort key, if applicable) of the target item.
  • UpdateExpression: A string that specifies the actions to perform on the attributes. It supports four primary action clauses:
    • SET: Adds one or more attributes and values to an item, or updates existing ones.
    • REMOVE: Deletes one or more specific attributes from an item.
    • ADD: Increments or decrements a numeric value, or appends elements to a set. (For numbers, SET myNumber = myNumber + :val is preferred in modern implementations).
    • DELETE: Removes elements from a set.
  • ExpressionAttributeValues: Substitutes tokens used in expressions with actual values (e.g., :val1), avoiding issues with literal values.
  • ExpressionAttributeNames: Resolves conflicts when attribute names collide with DynamoDB reserved keywords (e.g., #st for status).

Atomic Counters and Concurrency

A major advantage of the UpdateItem operation is its ability to perform atomic updates without locking. By using expressions such as SET viewCount = viewCount + :incr, multiple processes can safely increment or decrement numeric attributes concurrently without overwriting each other’s changes.

Additionally, you can include a ConditionExpression to ensure the update only takes place if specific criteria are met (for example, checking if a version number matches or verifying that the item already exists using attribute_exists()).

Returning Updated Values

To observe the changes made by the operation without making a secondary GetItem call, use the ReturnValues parameter. This can be configured to return:

  • NONE: Returns nothing (default, most cost-effective).
  • ALL_OLD: Returns the entire item as it appeared before the update.
  • UPDATED_OLD: Returns only the updated attributes as they appeared before the update.
  • ALL_NEW: Returns the entire item as it appears after the update.
  • UPDATED_NEW: Returns only the attributes that were affected by the update.
