DynamoDB Read Capacity: Strong vs Eventual Consistency

Amazon DynamoDB provisions throughput using Read Capacity Units (RCUs), where the consumed capacity of a read request depends directly on the item's size and the chosen read consistency model. DynamoDB rounds the size of an item up to the nearest 4 KB increment before calculating throughput. Based on that rounded size, strongly consistent reads consume full capacity units to guarantee real-time accuracy, whereas eventually consistent reads consume half the capacity by accepting a slight delay in data replication across storage nodes.

The Read Capacity Unit (RCU) Baseline

A single Read Capacity Unit represents one strongly consistent read per second, or two eventually consistent reads per second, for an item up to 4 KB in size.

When DynamoDB evaluates the consumed read capacity for an operation, it always rounds the item size up to the next 4 KB multiple:

  • An item of 1.5 KB is rounded up to 4 KB.
  • An item of 4.1 KB is rounded up to 8 KB.
  • An item of 11.2 KB is rounded up to 12 KB.

Strongly Consistent Reads

A strongly consistent read returns a result that reflects all successful write operations that occurred before the read request. To guarantee this level of consistency, DynamoDB queries the leader node or a majority of storage replicas.

Because this operation requires higher internal overhead, DynamoDB charges 1 full RCU for every 4 KB of data read.

Formula: Consumed RCUs = CEILING(Item Size in KB / 4 KB) * 1

Examples:

  • A 3 KB item requires 1 RCU.
  • A 6 KB item rounds up to 8 KB and requires 2 RCUs.
  • A 13 KB item rounds up to 16 KB and requires 4 RCUs.

Eventually Consistent Reads

An eventually consistent read maximizes read throughput by querying any available storage replica. While the response might not immediately reflect the results of a recently completed write, it typically replicates across all nodes within a second.

Because of the reduced system overhead, DynamoDB provides a 50 percent discount for eventually consistent reads. It charges 0.5 RCUs for every 4 KB of data read.

Formula: Consumed RCUs = CEILING(Item Size in KB / 4 KB) * 0.5

Examples:

  • A 3 KB item requires 0.5 RCUs.
  • A 6 KB item rounds up to 8 KB and requires 1 RCU.
  • A 13 KB item rounds up to 16 KB and requires 2 RCUs.

Batch and Multi-Item Reads

When performing batch operations such as BatchGetItem, DynamoDB calculates the consumed capacity for each item individually. It rounds each item up to the next 4 KB increment first and then applies the consistency multiplier, rather than aggregating the total payload size before rounding.

For Query or Scan operations reading multiple items, DynamoDB aggregates the total size of all items returned, rounds that total up to the nearest 4 KB boundary, and then calculates the consumed read capacity based on the consistency mode selected.
