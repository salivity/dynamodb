DynamoDB Write Capacity: Item Creation vs Deletion

Amazon DynamoDB measures database throughput using Write Capacity Units (WCUs), where one standard WCU represents one write per second for an item up to 1 KB in size. While both creating and deleting items consume write capacity, DynamoDB evaluates their consumption using fundamentally different criteria: item creation calculates capacity based on the size of the incoming data, whereas item deletion calculates capacity based on the size of the existing data being removed. This guide breaks down the specific calculation rules, non-existent item behaviors, and secondary index impacts for both operations.

Understanding the Standard Write Capacity Unit (WCU)

DynamoDB uses the Write Capacity Unit as the standard metric for write operations across provisioned and on-demand modes. For standard writes:

  • 1 WCU can write an item up to 1 KB in size.
  • Any item exceeding a 1 KB boundary is rounded up to the next full kilobyte. For example, a write of 1.2 KB consumes 2 WCUs, and a write of 2.1 KB consumes 3 WCUs.

Write Unit Consumption for Item Creation (PutItem)

When creating a new item using operations like PutItem, DynamoDB calculates the write unit consumption directly from the total payload size of the item being created.

  • Size Calculation: DynamoDB sums the length of all attribute names and attribute values in the new item.
  • WCU Formula: The total size is rounded up to the nearest 1 KB multiplier. An item of 500 bytes consumes 1 WCU. An item of 3.4 KB consumes 4 WCUs.
  • Overwrites: If a PutItem call replaces an existing item with the same primary key, DynamoDB still charges based entirely on the size of the new incoming item, completely ignoring the size of the item being replaced.
  • Failed Conditional Writes: If an item creation request includes a condition expression (e.g., attribute_not_exists(pk)) and that condition fails, DynamoDB still consumes write capacity (at least 1 WCU) to evaluate the existing item.

Write Unit Consumption for Item Deletion (DeleteItem)

When removing an item using DeleteItem, write consumption is not based on the size of the primary key passed in the request. Instead, it is determined by the data stored in the table.

  • Size Calculation: DynamoDB measures the total size of the existing item stored in the table, including all of its attribute names and values.
  • WCU Formula: The consumed capacity equals the stored item's size rounded up to the nearest 1 KB increment. Deleting a stored item that measures 4.5 KB consumes 5 WCUs.
  • Non-Existent Items: If a DeleteItem request targets a primary key that does not exist in the table, DynamoDB still consumes 1 WCU. The system must attempt the write operation to confirm the key's absence.
  • Conditional Deletes: If a conditional check on a delete request fails, DynamoDB consumes write capacity based on the size of the existing item evaluated.

Secondary Index Considerations

Both item creation and deletion trigger write consumption on Local Secondary Indexes (LSIs) and Global Secondary Indexes (GSIs):

  • Item Creation: If the new item contains the partition or sort key of an index, a corresponding write occurs on that index. Capacity consumed on the index is based on the size of the projected attributes for that item, rounded up to the next 1 KB increment.
  • Item Deletion: Deleting an item removes its corresponding entries across all populated secondary indexes. The deletion consumes write capacity on each index equal to the size of the projected attributes being removed, rounded up to the nearest 1 KB.
