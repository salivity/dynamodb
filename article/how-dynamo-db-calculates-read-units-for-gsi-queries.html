How DynamoDB Calculates Read Units for GSI Queries

Querying a Global Secondary Index (GSI) in Amazon DynamoDB consumes read capacity units (RCUs) directly from the index’s provisioned or on-demand capacity rather than the base table. The consumed read units depend on the total aggregate size of the items evaluated, the rounding rules applied to data blocks, and the consistency model supported by secondary indexes.

The GSI Consistency Model

Global Secondary Indexes only support eventually consistent reads. A strongly consistent read cannot be requested against a GSI. Under DynamoDB's standard pricing model:

  • One Read Capacity Unit (RCU) represents one strongly consistent read per second for an item up to 4 KB in size.
  • For eventually consistent reads, one RCU provides two reads per second for items up to 4 KB.

Consequently, each 4 KB read evaluated from a GSI costs 0.5 RCU.

Aggregate Size Calculation

Unlike single-item operations (such as GetItem), a Query operation calculates capacity across the entire operation rather than item by item.

  1. Sum the Data Size: DynamoDB calculates the size of all items matching the partition key and sort key conditions.
  2. Apply Rounding: The total aggregate size of all matched items is rounded up to the nearest 4 KB increment.
  3. Calculate Capacity Units: The rounded total is divided by 4 KB and then multiplied by 0.5 (for eventual consistency).

For example, if a query returns 10 items that total 6 KB in aggregate:

  • The 6 KB total is rounded up to the next 4 KB boundary: 8 KB.
  • 8 KB divided by 4 KB equals two 4 KB chunks.
  • At 0.5 RCU per 4 KB chunk, the query consumes 1.0 RCU.

Impact of Projected Attributes

Only attributes projected into the GSI contribute to the item size calculation. When an index is defined, it uses one of three projection types:

  • KEYS_ONLY: Only index keys and base table primary keys are stored. This results in the smallest item size and lowest read unit consumption.
  • INCLUDE: Specified non-key attributes are stored alongside the keys.
  • ALL: All attributes from the base table are replicated to the index, resulting in the largest item sizes and higher consumed capacity per query.

Impact of Filter Expressions

If a query includes a FilterExpression, the read units consumed do not decrease. DynamoDB evaluates all items matching the partition key and sort key conditions before applying the filter. The capacity consumed reflects the total size of all evaluated items prior to filtering, not just the filtered results returned to the client.
