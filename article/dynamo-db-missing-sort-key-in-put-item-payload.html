DynamoDB Missing Sort Key in PutItem Payload

When performing a PutItem operation on an Amazon DynamoDB table configured with a composite primary key, omitting the sort key attribute from the payload will cause the request to fail immediately. DynamoDB strictly requires all primary key attributes to be present in write payloads, and a missing sort key results in a ValidationException without modifying the table.

The Result: ValidationException

If a table is defined with both a partition key (HASH) and a sort key (RANGE), any PutItem API call missing the sort key attribute will be rejected by DynamoDB. The service returns a 400 Bad Request HTTP status code accompanied by a ValidationException.

The returned error message typically states:

ValidationException: One of the required keys was not given a value

Because DynamoDB evaluates the primary key structure before executing the write, the operation is completely synchronous and atomic in its failure. No partial item is written, and no other attributes in the payload are stored.

Why DynamoDB Enforces the Sort Key

In DynamoDB, a primary key uniquely identifies every item in a table. Tables can use one of two primary key schemas:

  1. Simple Primary Key: Consists solely of a partition key.
  2. Composite Primary Key: Consists of a partition key and a sort key.

For tables using a composite key, DynamoDB stores physical items grouped by the partition key and sorted by the sort key within that partition. The combination of both keys forms the unique identifier for the item. DynamoDB does not provide automatic generation, null fallbacks, or default values for missing primary key attributes. Without the sort key, DynamoDB cannot determine the item's identity, detect whether it should overwrite an existing record, or place it in the underlying storage partition.

How to Prevent and Handle the Error

To avoid a ValidationException during PutItem requests:

  • Validate the Payload Schema: Ensure data validation layers (such as JSON schemas or ORM/ODM models) require both the partition key and sort key fields before dispatching the network request to DynamoDB.
  • Assign Explicit Default Values: If an item naturally lacks a distinct sort dimension, supply a static, recognized placeholder value (for example, METADATA or INFO) as the sort key.
  • Catch the Exception: Implement error handling in your application code to catch ValidationException or the specific SDK equivalent (such as DynamoDbException or ClientError) to log the missing attribute and handle the failure gracefully.
