What Happens to DynamoDB LSIs When Items Are Deleted

When you delete an item from an Amazon DynamoDB base table, any corresponding entry in a Local Secondary Index (LSI) is automatically and synchronously deleted. This article explains how DynamoDB manages LSI maintenance during base table deletions, the impact on consumed write capacity units (WCUs), and how this process differs from global secondary indexes.

Automatic and Synchronous Deletion

An LSI shares the same partition key as the base table, differing only by its sort key. Because the index data resides on the same physical storage partition as the base table data, DynamoDB manages LSIs within the exact same transaction boundary.

When a DeleteItem operation is executed on the base table:

  • DynamoDB locates the item in the base partition.
  • It identifies any corresponding projected entries in the table's LSIs.
  • It deletes both the base table item and the LSI entries simultaneously.

There is no delay or eventual consistency gap. As soon as the deletion succeeds on the base table, subsequent queries against the LSI will immediately reflect that the item no longer exists.

Impact on Write Capacity Units (WCU)

Deleting an item that exists in an LSI consumes additional write capacity. The consumed write throughput depends on the size of the item and its index projections:

  • Base Table Consumption: Write units are charged based on the full size of the item being removed from the base table.
  • LSI Consumption: Write units are additionally charged to delete the index entry. The calculation considers the size of the indexed partition key, the LSI sort key, and any projected attributes.
  • Sparse Index Exemption: If the deleted base table item did not contain the LSI's sort key attribute, the item was never indexed. In this scenario, no LSI deletion occurs, and no additional write capacity is consumed for that index.

All consumed capacity is billed against the base table's provisioned or on-demand write capacity, as LSIs do not have separate capacity allocations.

Atomicity and Transactions

LSI updates are atomic. If a DeleteItem request fails due to a conditional check failure, insufficient capacity, or a system error, the operation aborts completely. DynamoDB will not delete the base table item while leaving the LSI entry behind, nor will it remove the index entry while the base item persists. When using TransactWriteItems, this atomicity extends across all operations within the transaction scope.
