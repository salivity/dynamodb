DynamoDB Binary and Binary Set Data Types Explained

Amazon DynamoDB natively supports raw binary data using the Binary (B) and Binary Set (BS) attribute types to store non-text payloads such as encrypted text, compressed documents, serialized objects, or image thumbnails. This article explains how DynamoDB handles the encoding, storage limits, uniqueness constraints, and key indexing of both binary scalar types and binary set attributes.

Binary Data Type (B)

The Binary (B) scalar type stores arbitrary binary data. DynamoDB does not alter or format the underlying raw bytes, allowing any binary format to be stored directly within an item.

  • Base64 Encoding: Because DynamoDB communicates using JSON over HTTP APIs, all binary data sent to DynamoDB must be Base64-encoded in API requests. Most AWS SDKs automatically handle this encoding and decoding.
  • Storage and Size Calculation: DynamoDB evaluates binary size based on the decoded raw byte count, not the Base64 representation. The attribute name length plus the actual raw byte length counts toward DynamoDB’s maximum item size limit of 400 KB.
  • Usage as Primary Keys: A Binary attribute can be used as a Partition Key or a Sort Key. When evaluated as a sort key or compared in conditional expressions, DynamoDB compares binary values lexicographically using unsigned byte values (byte-by-byte comparison).

Binary Set Data Type (BS)

The Binary Set (BS) attribute type represents a collection of distinct binary values.

  • Element Uniqueness: Every element within a Binary Set must be unique. If an application attempts to write duplicate binary elements to the same set within an update, DynamoDB will reject the request with a validation error.
  • Unordered Nature: DynamoDB does not preserve the order of elements within a Binary Set. Applications should not rely on element sequence when retrieving set data.
  • Empty Set Restrictions: DynamoDB sets cannot be empty. A Binary Set must contain at least one binary value; attempting to save an empty set results in an error.
  • Usage Constraints: Binary Sets cannot be used as primary keys (neither as a partition key nor a sort key). They can only exist as standard attributes within an item.
  • Size Calculation: The size impact of a Binary Set is calculated as the length of the attribute name plus the sum of the raw decoded byte sizes of each individual binary element in the set.

Comparison and Conditional Logic

DynamoDB allows conditional operations and queries on Binary attributes:

  • Scalar Binary (B): Supports operators such as =, <>, <, <=, >, >=, and BEGINS_WITH for range queries and sorting.
  • Binary Set (BS): Supports the CONTAINS function to verify the presence of a specific binary element within the set, as well as set-level update operations like ADD and DELETE to append or remove specific binary elements without overwriting the entire set.
