Calculating DynamoDB Transactional Read Capacity

Understanding how Amazon DynamoDB calculates Read Capacity Units (RCUs) for transactional reads is essential for designing high-performance applications while managing cloud infrastructure costs. This article explains the exact formula DynamoDB uses to measure throughput consumption during TransactGetItems operations, how item sizes are rounded, and how multiple read operations within a single transaction aggregate into total consumed capacity.

The Basic Unit of Measurement

In standard DynamoDB operations, one Read Capacity Unit (RCU) represents one strongly consistent read per second for an item up to 4 KB in size, or two eventually consistent reads per second for an item up to 4 KB.

Transactional read requests, executed using the TransactGetItems API, provide ACID isolation and atomicity across one or more items. Because of the coordination and locking overhead required to guarantee serializability, DynamoDB doubles the baseline cost: one transactional read requires 2 RCUs for each 4 KB chunk of data read.

The Calculation Rule

To determine the RCUs consumed by a transactional read request, DynamoDB applies the following process:

  1. Calculate Individual Item Sizes: DynamoDB evaluates each item requested in the transaction independently. The size of an item includes both the attribute names and their corresponding values.
  2. Round Up to the Nearest 4 KB: The size of each item is rounded up to the next 4 KB boundary. If an item is smaller than 4 KB, it is rounded up to 4 KB.
  3. Apply the 2x Multiplier: DynamoDB assigns 2 RCUs for every 4 KB increment.
  4. Aggregate the Total: The consumed capacity units for all individual items within the transaction are summed together to determine the total RCUs consumed by the call.

The formula per item is: \[\text{Consumed RCUs} = \left\lceil \frac{\text{Item Size in KB}}{4\text{ KB}} \right\rceil \times 2\]

Examples

  • Single small item (under 4 KB): Reading an item that is 2.5 KB rounds up to 4 KB. At 2 RCUs per 4 KB, the transaction consumes 2 RCUs.
  • Single larger item (over 4 KB): Reading an item that is 6 KB rounds up to 8 KB (two 4 KB increments). Consuming 2 RCUs per 4 KB chunk results in 4 RCUs.
  • Multiple items in a single transaction: If a TransactGetItems request retrieves:
    • Item A: 1.5 KB (rounds up to 4 KB \(\rightarrow\) 2 RCUs)
    • Item B: 7.2 KB (rounds up to 8 KB \(\rightarrow\) 4 RCUs)
    • Item C: 11.8 KB (rounds up to 12 KB \(\rightarrow\) 6 RCUs)
    The total consumed throughput for the transaction is \(2 + 4 + 6 = \mathbf{12\text{ RCUs}}\).

Additional Constraints

  • No Cross-Item Bundling: DynamoDB does not combine the sizes of multiple items before rounding. Two separate 1 KB items in the same transaction consume 4 RCUs total (2 RCUs each), not 2 RCUs.
  • Transaction Limits: A single TransactGetItems operation can include up to 100 items or up to 4 MB of total data, whichever limit is reached first.
  • Missing Items: If an item specified in a TransactGetItems call does not exist, DynamoDB still consumes 2 RCUs for evaluating that item's key.
