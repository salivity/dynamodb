DynamoDB Data Types: Working with Sets, Maps, Lists

Amazon DynamoDB provides built-in support for complex data structures, specifically sets, lists, and maps, enabling developers to store rich, structured, and hierarchical data within a single item. Sets represent unique, unordered collections of a single scalar type, while lists and maps represent ordered and key-value document structures that can nest heterogeneous data. Understanding how DynamoDB stores, updates, and limits these types is essential for designing efficient NoSQL schemas and optimizing document-based queries.

Sets (SS, NS, BS)

DynamoDB supports three types of sets: String Sets (SS), Number Sets (NS), and Binary Sets (BS).

  • Type Homogeneity: Every element in a set must be of the same scalar type. For example, a Number Set cannot contain strings.
  • Uniqueness: All elements within a set must be unique. If an application attempts to write duplicate values to a set, DynamoDB deduplicates them automatically.
  • Unordered Nature: Sets do not preserve the order of their elements. Applications should not rely on element positioning.
  • Non-Empty Requirement: DynamoDB does not allow empty sets. If an update removes all elements from a set, the attribute itself must be deleted or DynamoDB will return a validation error.
  • Atomic Updates: DynamoDB supports native ADD and DELETE operations in update expressions for sets, allowing developers to add or remove specific items without reading the entire array first.

Lists (L)

A list (L) is an ordered collection of values, directly analogous to an array in JSON.

  • Heterogeneous Elements: Unlike sets, lists can store mixed data types within the same collection, including strings, numbers, booleans, maps, and even nested lists.
  • Order and Duplicates: Lists maintain the exact order in which elements are inserted and allow duplicate values.
  • Indexed Access: Elements are referenced by their zero-based index. Using DynamoDB update expressions, you can modify or delete specific elements directly (for example, SET comments[0].status = :approved) or append new elements to the end using the list_append() function.
  • Empty Values: Unlike sets, lists can be empty ([]).

Maps (M)

A map (M) is an unordered collection of key-value pairs, functionally equivalent to a JSON object.

  • Schema Flexibility: Maps allow arbitrary nesting of attributes. Keys must be strings, but the corresponding values can be any supported DynamoDB data type, including scalars, sets, lists, or other maps.
  • Deep Nesting: DynamoDB allows documents to be nested up to 32 levels deep.
  • Dot Notation Updates: Attributes inside maps can be queried and updated granularly using dot notation (for example, SET address.geo.latitude = :lat) without overwriting the entire parent map.

Key Considerations and Limitations

  • Item Size Limit: All sets, lists, and maps contribute directly to DynamoDB’s strict 400 KB maximum item size limit. Storing unbounded collections (such as an ever-growing list of transaction logs) inside a single item can lead to the item exceeding this limit.
  • Key Constraints: Sets, lists, and maps cannot serve as partition keys or sort keys for tables, Local Secondary Indexes (LSIs), or Global Secondary Indexes (GSIs). Primary keys must always be scalar types: String, Number, or Binary.
  • Projection and Filtering: You can use projection expressions to retrieve only specific elements of a list or map, reducing network transfer overhead, though the full item is still read from disk for capacity unit calculations.
