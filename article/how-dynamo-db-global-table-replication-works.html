How DynamoDB Global Table Replication Works

Amazon DynamoDB Global Tables rely on a fully managed, active-active replication system that automatically synchronizes data across your chosen AWS regions. When an application writes an item to a local replica table, DynamoDB captures the modification and asynchronously pushes the changes to all other regional replicas over the private AWS global network. This article explains the underlying mechanism of DynamoDB cross-region data transfers, detailing how change data capture, network routing, and conflict resolution work together to ensure multi-region consistency.

Change Data Capture via DynamoDB Streams

The replication process begins at the storage layer of the source region. Whenever an item is created, updated, or deleted in a replica table, DynamoDB automatically records the event using an internal implementation of DynamoDB Streams. This stream creates an ordered, time-sequenced log of item-level modifications. Because this mechanism functions at the storage engine level, the write operation completes locally with single-digit millisecond latency before the cross-region replication process even begins.

Cross-Region Propagation Over the AWS Global Network

Once an update is committed to the local stream, DynamoDB's internal replication fleet reads the change records. The service packages these mutations and transmits them to the destination regions via AWS's dedicated, private fiber-optic backbone rather than the public internet. This private network infrastructure minimizes packet loss, provides predictable throughput, and encrypts all data in transit using Transport Layer Security (TLS).

Because this process is asynchronous, cross-region replication does not block local write operations. The time it takes for a write to propagate to other regions is typically under a second, though it depends on the physical distance between regions and current network conditions.

Applying Changes and Conflict Resolution

When the target region receives the replicated stream records, the local DynamoDB infrastructure applies the updates directly to the replica table. If applications update the same item concurrently in two different regions, DynamoDB uses a "Last Writer Wins" (LWW) conflict resolution strategy.

Under the Last Writer Wins model, DynamoDB compares the timestamps of the conflicting writes. The write with the latest timestamp is preserved across all replicas, ensuring that all tables eventually converge to the exact same state.

Consistency and Billing Characteristics

DynamoDB cross-region replication operates on an eventual consistency model. Reads against a local replica return strongly consistent data only for writes that originated in that specific region; data replicated from other regions is eventually consistent.

From a resource standpoint, cross-region data transfers incur standard AWS cross-region data transfer fees, alongside replicated write capacity units (rWCUs) consumed on each destination replica to apply the incoming mutations.
