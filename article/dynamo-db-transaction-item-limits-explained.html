DynamoDB Transaction Item Limits Explained

Amazon DynamoDB provides atomic, consistent, isolated, and durable (ACID) operations through its transaction APIs, but these operations are bounded by specific capacity and item thresholds. This guide outlines the exact limits on the number of items that can be processed in a single DynamoDB transaction, covering the maximum item counts, payload restrictions, and structural operational rules you must follow when designing transactional workflows.

Maximum Item Count Limit

In Amazon DynamoDB, a single transaction can process a maximum of 100 items. This limit applies uniformly to both primary transactional operations:

  • TransactWriteItems: Allows you to group up to 100 write actions—including Put, Update, Delete, and ConditionCheck requests—into a single, coordinated, all-or-nothing operation.
  • TransactGetItems: Allows you to retrieve up to 100 individual items atomically across one or more tables within the same AWS account and region.

(Note: While the original service limit was 25 items at launch, AWS expanded this threshold to 100 items per transaction.)

Payload and Data Size Restrictions

In addition to the 100-item limit, transactions are governed by strict data volume ceilings:

  • Aggregate Transaction Size: The combined size of all items, keys, and expressions in a single transaction cannot exceed 4 MB.
  • Individual Item Size: Standard DynamoDB rules apply; no single item in the transaction can exceed the platform limit of 400 KB.

If the sum of all items in your transaction exceeds 4 MB, the entire transaction will be rejected, even if you are processing fewer than 100 items.

Key Operational Constraints

When working within the 100-item transaction limit, several behavioral rules dictate how items can be targeted:

  • No Duplicate Item Actions: In a TransactWriteItems call, you cannot perform multiple actions on the same item within the same request. For instance, you cannot update an item and perform a condition check on it in the same transaction.
  • Condition Checks Count as Items: A standalone ConditionCheck action does not write data, but it verifies an item's state. Each ConditionCheck consumes one slot toward the 100-item maximum.
  • Cross-Table Operations: The 100 items can span across multiple tables within the same AWS Region and account. The 100-item cap applies to the cumulative total across all involved tables, not 100 items per table.
  • Atomicity Overhead: If any single action or condition check fails within the set of items, the entire transaction is cancelled, and none of the changes are applied.
