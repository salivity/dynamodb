IAM Permission to Create and Delete DynamoDB Indexes

Managing Amazon DynamoDB secondary indexes requires specific AWS Identity and Access Management (IAM) permissions depending on whether the index is established during initial table deployment or on an existing table. This guide explains the exact IAM actions required to create and delete Global Secondary Indexes (GSIs) and Local Secondary Indexes (LSIs), specifically focusing on the dynamodb:UpdateTable permission used for ongoing index management.

The Required IAM Action: dynamodb:UpdateTable

Amazon DynamoDB does not have dedicated standalone IAM actions such as CreateIndex or DeleteIndex. Instead, modifications to indexes on an existing table are handled through the UpdateTable API operation.

To create or delete a Global Secondary Index (GSI) on an existing DynamoDB table, an IAM identity must have permission for:

  • dynamodb:UpdateTable

When you initiate a GSI creation or deletion via the AWS Management Console, AWS CLI, or an SDK, DynamoDB executes an UpdateTable request containing the GlobalSecondaryIndexUpdates parameter. Without the dynamodb:UpdateTable permission, the request fails with an AccessDeniedException.

Table Creation Permissions: dynamodb:CreateTable

The creation of Local Secondary Indexes (LSIs), as well as any initial GSIs defined at table launch, requires:

  • dynamodb:CreateTable

  • Local Secondary Indexes (LSIs): Can only be created when the table is created. Once the table exists, LSIs cannot be added, modified, or deleted.

  • Global Secondary Indexes (GSIs): Can be created alongside the table using dynamodb:CreateTable, or managed dynamically later using dynamodb:UpdateTable.

Example IAM Policy

To grant a user or role permission to create and delete GSIs on a specific DynamoDB table, attach an IAM policy granting the dynamodb:UpdateTable action for that resource:

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowIndexManagementViaUpdateTable",
            "Effect": "Allow",
            "Action": [
                "dynamodb:UpdateTable",
                "dynamodb:DescribeTable"
            ],
            "Resource": "arn:aws:dynamodb:region:account-id:table/your-table-name"
        }
    ]
}

Note: Including dynamodb:DescribeTable is standard practice, as it allows users and tools to monitor the status (CREATING, ACTIVE, DELETING) of the index as it builds or tears down.
