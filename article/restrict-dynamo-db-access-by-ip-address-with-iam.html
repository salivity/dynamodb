Restrict DynamoDB Access by IP Address with IAM

Securing Amazon DynamoDB databases often requires limiting access strictly to trusted network perimeters such as corporate networks or designated bastion hosts. In AWS Identity and Access Management (IAM), access can be enforced at the network level by evaluating incoming requests against defined CIDR blocks. This article identifies the specific IAM condition key used to restrict DynamoDB API calls to approved source IP addresses, explains how it works, and provides a production-ready policy example.

The IAM Condition Key: aws:SourceIp

The primary IAM condition key used to restrict DynamoDB API access to specific IP addresses is aws:SourceIp.

aws:SourceIp is an AWS global condition key. When an API call is made to DynamoDB, AWS evaluates the public IPv4 or IPv6 address originating the request against the value defined in the IAM policy.

How aws:SourceIp Works

The aws:SourceIp key is paired with IP condition operators:

  • IpAddress: Grants access only if the request originates from the specified IP address or CIDR block.
  • NotIpAddress: Denies or allows access if the request does not originate from the specified IP address or range.

In security-focused architectures, it is best practice to implement explicit deny rules. In IAM, an explicit deny always overrides an allow. Using Effect: Deny combined with the NotIpAddress operator ensures that any request coming from outside your authorized IP range is immediately blocked, regardless of other permissions.

Example IAM Policy

Below is an IAM policy that denies all DynamoDB actions if the request originates from outside the authorized IP range 203.0.113.0/24:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyDynamoDBAccessOutsideSpecificIP",
      "Effect": "Deny",
      "Action": "dynamodb:*",
      "Resource": "*",
      "Condition": {
        "NotIpAddress": {
          "aws:SourceIp": [
            "203.0.113.0/24"
          ]
        },
        "Bool": {
          "aws:ViaAWSService": "false"
        }
      }
    }
  ]
}

Note: Adding "aws:ViaAWSService": "false" ensures that requests made on your behalf by other AWS services (such as AWS Lambda interacting directly with DynamoDB inside the AWS infrastructure) are not inadvertently blocked by the IP restriction.

Key Considerations

  1. VPC Endpoints (PrivateLink): If traffic to DynamoDB is routed internally through an AWS VPC Gateway Endpoint or Interface Endpoint, the public IP is not preserved. In these scenarios, aws:SourceIp will not match public IP addresses. Instead, use condition keys like aws:sourceVpce (VPC endpoint ID) or aws:VpcSourceIp (private IP address within the VPC).
  2. Proxies and NAT Gateways: aws:SourceIp evaluates the IP address seen by the AWS endpoint. If your traffic passes through a corporate proxy, VPN, or NAT Gateway, use the public-facing egress IP of that gateway rather than individual client private IPs.
