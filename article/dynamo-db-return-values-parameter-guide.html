DynamoDB ReturnValues Parameter Guide

In Amazon DynamoDB, the ReturnValues parameter controls what item attributes the service returns in its response after executing a write operation. By default, write requests return empty responses to conserve bandwidth. Configuring ReturnValues allows developers to inspect an item's previous or newly modified state directly within the response of a PutItem, UpdateItem, or DeleteItem call, eliminating the need to issue a separate GetItem request.

Primary Purposes of ReturnValues

  1. Eliminate Extra Read Requests: Instead of issuing a write followed by a read to verify data changes, ReturnValues provides the required item attributes within the write operation's response. This reduces network round-trips and overall application latency.
  2. Retrieve Values from Atomic Updates: When performing mathematical operations (such as incrementing a counter using ADD in an UpdateItem expression), the application often needs to know the final value. ReturnValues supplies the resulting value immediately.
  3. Capture State Changes for Concurrency Control: When items are updated or deleted conditionally, accessing the pre-existing state helps applications track changes, log audit trails, or resolve conflicts without additional lookups.

Supported Options by Operation

The behavior of ReturnValues depends on the specific write operation being executed.

For UpdateItem

UpdateItem offers the most flexibility, supporting five distinct values:

  • NONE (Default): DynamoDB returns nothing in the response.
  • ALL_OLD: Returns all attributes of the item as they existed immediately prior to the update.
  • ALL_NEW: Returns all attributes of the item as they exist immediately after the update.
  • UPDATED_OLD: Returns only the specific attributes that were changed, showing their values as they existed before the update.
  • UPDATED_NEW: Returns only the specific attributes that were changed, showing their values as they exist after the update.

For PutItem and DeleteItem

PutItem and DeleteItem operate on whole items rather than partial updates, so they support fewer options:

  • NONE (Default): DynamoDB returns nothing in the response.
  • ALL_OLD: Returns all attributes of the item as they existed prior to being overwritten by PutItem or removed by DeleteItem.

Note: ALL_NEW, UPDATED_OLD, and UPDATED_NEW are not valid for PutItem or DeleteItem.

Throughput and Cost Impact

Requesting attributes via ReturnValues does not consume additional Read Capacity Units (RCUs). The operation is billed solely as a write operation based on the item's size. However, returning large payloads increases response payload size and network bandwidth consumption, so ReturnValues should only be configured when the client application actively requires the returned data.
