DynamoDB Query Result Continuation

Amazon DynamoDB limits query result sizes to 1 MB of data or a specified limit, requiring pagination to retrieve large datasets across multiple requests. To resume a query from where the previous operation stopped, DynamoDB uses the ExclusiveStartKey parameter. This guide explains how ExclusiveStartKey works, how it pairs with LastEvaluatedKey, and how to implement it to fetch paginated results efficiently.

The Role of ExclusiveStartKey

The ExclusiveStartKey parameter dictates the primary key of the item from which DynamoDB should begin evaluating results. When supplied in a Query or Scan request, DynamoDB starts reading items immediately after the item specified by this key. It prevents duplicate reads by excluding the item itself from the new result set.

How Pagination Works in DynamoDB

DynamoDB query continuation follows a two-part request-and-response cycle:

  1. Receive LastEvaluatedKey: When a query has more matching items than can be returned in a single response, the response object includes a LastEvaluatedKey. This key contains the partition key (and sort key, if applicable) of the last item processed.
  2. Pass as ExclusiveStartKey: In the subsequent request, set the ExclusiveStartKey parameter equal to the LastEvaluatedKey from the prior response.
  3. Repeat Until Completion: Continue this loop until the response no longer contains a LastEvaluatedKey, indicating that all matching records have been retrieved.

Key Considerations

  • Key Structure: The value assigned to ExclusiveStartKey must match the primary key schema of the table or secondary index being queried. For tables with a composite primary key, both the partition key and sort key attributes must be provided.
  • Filter Expressions: DynamoDB applies a FilterExpression after reading items. If a query returns an empty list of items but still contains a LastEvaluatedKey, the operation must continue using that key until LastEvaluatedKey is absent.
  • Stateless Pagination: Because ExclusiveStartKey contains actual primary key values rather than an offset or cursor index, pagination remains stable and deterministic even if other items are inserted or removed elsewhere in the table.
