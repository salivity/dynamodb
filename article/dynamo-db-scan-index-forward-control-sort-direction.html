DynamoDB ScanIndexForward: Control Sort Direction

In Amazon DynamoDB, the ScanIndexForward parameter controls the sort order of items returned by a Query operation. This article explains how ScanIndexForward uses a table's sort key to dictate sorting, how its boolean values invert result orders, and how it interacts with query limits and pagination.

How ScanIndexForward Operates

In DynamoDB, data within a single partition key is physically ordered by the sort key (also known as the range key). The ScanIndexForward parameter is a boolean attribute used exclusively in Query requests to determine the direction in which DynamoDB traverses these sort key values.

The parameter behaves according to two states:

  • true (Default): DynamoDB traverses the partition in ascending order. Numeric sort keys appear from lowest to highest, string values appear in UTF-8 binary encoding order (alphabetical, A–Z), and date/timestamp strings order from oldest to newest. If you omit the parameter, DynamoDB automatically assumes ScanIndexForward: true.
  • false: DynamoDB traverses the partition in descending order. Numeric sort keys appear from highest to lowest, strings reverse from Z–A, and timestamps return from newest to oldest.

Because this parameter depends on a sequence of sort keys, it only applies to tables or Secondary Indexes (Local Secondary Indexes or Global Secondary Indexes) that have a composite primary key consisting of both a partition key and a sort key. It cannot be used with a Scan operation, which does not return sorted data.

Interaction with the Limit Parameter

The traversal direction directly impacts how DynamoDB applies the Limit parameter.

DynamoDB applies the Limit during query execution after determining traversal direction, but before applying any FilterExpression.

  • If ScanIndexForward is true with a Limit of 5, DynamoDB reads the first 5 ascending items matching the partition key.
  • If ScanIndexForward is false with a Limit of 5, DynamoDB reads the top 5 descending items matching the partition key.

This mechanism makes setting ScanIndexForward: false with a Limit of 1 the standard pattern for retrieving the most recent entry in time-series data.

Pagination and LastEvaluatedKey

When a query result exceeds 1 MB or hits an explicit Limit, DynamoDB returns a LastEvaluatedKey.

To paginate:

  1. Provide the returned LastEvaluatedKey as the ExclusiveStartKey for the next request.
  2. Maintain the same ScanIndexForward setting across all paginated requests.

DynamoDB uses the sort key in ExclusiveStartKey as the starting point and continues scanning in the direction specified by ScanIndexForward. Changing the flag between pages will disrupt pagination and return duplicate or missed records.

Query Example

In the AWS SDK (v3 for JavaScript), a descending query on a partition looks like this:

import { DynamoDBClient } from "@aws-sdk/client-dynamodb";
import { QueryCommand, DynamoDBDocumentClient } from "@aws-sdk/lib-dynamodb";

const client = DynamoDBDocumentClient.from(new DynamoDBClient({}));

const params = {
  TableName: "UserActivity",
  KeyConditionExpression: "UserId = :userId",
  ExpressionAttributeValues: {
    ":userId": "USER#12345"
  },
  ScanIndexForward: false, // Descending order (newest items first)
  Limit: 10
};

const response = await client.send(new QueryCommand(params));

By switching ScanIndexForward to true, the same command returns the oldest 10 records for that user without requiring any index rebuilds or secondary index definitions.
