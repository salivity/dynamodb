Updating Nested Map Attributes in DynamoDB

Amazon DynamoDB allows you to modify deeply nested elements within a Map (M) data type without overwriting the entire parent structure. This article explains how DynamoDB interprets nested document paths in an update expression, the syntax required to target specific keys, the prerequisite conditions for parent elements, and how consumed write capacity is calculated during these operations.

Document Path Syntax

DynamoDB uses dot notation to traverse nested map structures within an UpdateExpression. To reach an attribute nested inside one or more maps, you specify the path sequentially from the top-level attribute down to the target key:

TopLevelMap.NestedMap.TargetKey

If an attribute name contains special characters, hyphens, or conflicts with DynamoDB reserved words (such as Status, Date, or Name), you must define expression attribute names using the # placeholder:

#topMap.#nestedMap.#targetKey

The SET Action and Parent Map Requirements

When you use the SET action to add or update a nested map key, DynamoDB checks the path sequentially:

  1. Existing Parents: If the parent map exists, DynamoDB creates the target key if it is absent or updates its value if it already exists. Sibling keys within the parent map remain entirely untouched.
  2. Missing Parents: DynamoDB cannot navigate through a non-existent map. If any intermediate parent in the path does not exist, the update operation fails and returns a ValidationException stating that the document path provided in the update expression is invalid.

To safely write to a nested path where intermediate maps may not exist, you must initialize parent maps first or compose expressions using the if_not_exists() function to establish the structure:

SET TopLevelMap = if_not_exists(TopLevelMap, :emptyMap)

The REMOVE Action on Nested Paths

To delete a single nested key from a map without affecting other elements, you use the REMOVE action followed by the document path:

REMOVE TopLevelMap.NestedMap.TargetKey

When this command executes, DynamoDB deletes only the targeted key-value pair. If TargetKey is the last remaining attribute inside NestedMap, the empty NestedMap object remains unless you explicitly remove the parent path. Attempting to REMOVE a path that already does not exist does not produce an error; DynamoDB simply performs no action.

Processing Semantics and Capacity Consumption

DynamoDB processes nested updates atomically at the item level. While update expressions reduce network payload size by only transmitting the path and the specific value being altered, DynamoDB still reads and writes the entire item under the hood.

Because of this, consumed Write Capacity Units (WCUs) are calculated based on the total size of the complete item before and after the update, rounded up to the nearest 1 KB increment, rather than the size of the specific nested attribute being modified.
