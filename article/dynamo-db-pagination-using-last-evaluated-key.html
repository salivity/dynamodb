DynamoDB Pagination Using LastEvaluatedKey

Amazon DynamoDB manages large query results by paginating data through the LastEvaluatedKey attribute and the ExclusiveStartKey parameter. When a Query or Scan operation exceeds the maximum 1 MB data limit or a user-defined item limit, DynamoDB returns a partial result set alongside a LastEvaluatedKey. This attribute acts as a bookmark, allowing subsequent requests to resume reading precisely where the previous operation stopped until the entire dataset is retrieved.

The 1 MB Limit and the Pagination Trigger

DynamoDB processes read requests in batches. A single Query or Scan operation reads up to a maximum of 1 MB of data from the table or index. Alternatively, developers can specify a Limit parameter to restrict the number of items evaluated in a single request.

If the operation evaluates 1 MB of data or reaches the specified Limit before evaluating all matching items, DynamoDB halts the execution, returns the items collected so far, and includes a LastEvaluatedKey in the response payload.

Structure of LastEvaluatedKey

The LastEvaluatedKey contains the primary key attributes of the last item that DynamoDB evaluated during the operation. Depending on the table schema or the index being queried, it consists of:

  • Partition Key only: If the table or index uses a simple primary key.
  • Partition Key and Sort Key: If the table or index uses a composite primary key.

If the read operation was performed on a Secondary Index (Global or Local), the LastEvaluatedKey includes both the index keys and the base table's primary keys to ensure exact position tracking.

Resuming Reads with ExclusiveStartKey

To fetch the next page of results, the client application must issue a new read request identical to the original (same key conditions, filters, and projections) while passing the received LastEvaluatedKey into the ExclusiveStartKey parameter.

  1. Request 1: The client sends a Query or Scan without an ExclusiveStartKey.
  2. Response 1: DynamoDB returns the first page of items and a LastEvaluatedKey.
  3. Request 2: The client sends the same request, setting ExclusiveStartKey equal to the LastEvaluatedKey from Response 1.
  4. Response 2: DynamoDB begins reading immediately after the item specified by ExclusiveStartKey.

This cycle repeats in a loop until DynamoDB returns a response that does not contain a LastEvaluatedKey. The absence of this key indicates that all matching records have been processed and pagination is complete.

FilterExpressions and Empty Responses

A common scenario in DynamoDB pagination involves FilterExpression. DynamoDB applies filter expressions after it reads items up to the 1 MB limit or item Limit.

Consequently, an operation might evaluate items, find that none match the filter, and return an empty Items array alongside a valid LastEvaluatedKey. In this case, pagination has not concluded; the client must continue passing the LastEvaluatedKey as the ExclusiveStartKey until the key is null, regardless of whether individual pages return empty result sets.
