DynamoDB Auto Scaling Max Throughput Setting

Amazon DynamoDB auto scaling automatically adjusts provisioned throughput capacity on your behalf in response to actual traffic patterns. The specific configuration parameter that controls the upper threshold of this throughput is MaxCapacity (labeled in the AWS Management Console as Maximum provisioned capacity units). This article breaks down how this parameter works, where it is configured, and how to apply it effectively to manage performance and prevent unexpected billing surges.

The Key Parameter: MaxCapacity

In AWS Application Auto Scaling—the underlying service that powers DynamoDB auto scaling—the maximum throughput allowed for a table or global secondary index (GSI) is determined by the MaxCapacity parameter.

This parameter defines the absolute highest number of capacity units that auto scaling can allocate, regardless of how high traffic spikes. It is configured independently for reads and writes across two scalable dimensions:

  • Read Capacity Units (RCUs): dynamodb:table:ReadCapacityUnits (or dynamodb:index:ReadCapacityUnits for GSIs)
  • Write Capacity Units (WCUs): dynamodb:table:WriteCapacityUnits (or dynamodb:index:WriteCapacityUnits for GSIs)

When target tracking policies detect that consumption exceeds the target utilization rate (such as 70%), the system increases capacity in increments up to, but never exceeding, the value set in MaxCapacity.

How to Configure MaxCapacity

The parameter can be defined across different deployment interfaces:

1. AWS Management Console

Under the Capacity settings of a DynamoDB table or secondary index:

  • Set the capacity mode to Provisioned.
  • Enable Auto scaling for read or write capacity.
  • Define the Maximum provisioned capacity units field.

2. AWS CLI

When registering a scalable target via the Application Auto Scaling CLI, use the --max-capacity flag:

aws application-autoscaling register-scalable-target \
    --service-namespace dynamodb \
    --resource-id table/MyTable \
    --scalable-dimension dynamodb:table:ReadCapacityUnits \
    --min-capacity 5 \
    --max-capacity 100

3. AWS CloudFormation

In CloudFormation, define the property within an AWS::ApplicationAutoScaling::ScalableTarget resource:

ScalableReadTarget:
  Type: AWS::ApplicationAutoScaling::ScalableTarget
  Properties:
    MaxCapacity: 100
    MinCapacity: 5
    ResourceId: table/MyTable
    ScalableDimension: dynamodb:table:ReadCapacityUnits
    ServiceNamespace: dynamodb

Impact of the Maximum Limit

  • Cost Protection: DynamoDB charges for provisioned capacity whether it is fully utilized or not. MaxCapacity acts as a cost ceiling, preventing runaway scaling events caused by sudden, massive traffic spikes or application bugs.
  • Throttling Risk: If application traffic demands more throughput than the configured MaxCapacity, DynamoDB will not scale further. Requests that exceed this ceiling will result in ProvisionedThroughputExceededException errors. Monitor CloudWatch metrics, specifically ThrottledRequests, to verify if the limit needs adjustment.
