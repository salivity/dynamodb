Verify DynamoDB Client-Side Encryption via CLI

This article explains how to verify client-side encryption configurations for Amazon DynamoDB using the AWS Command Line Interface (AWS CLI). You will learn how client-side encryption alters data before transmission, how to query DynamoDB using the standard AWS CLI to confirm that attributes are encrypted, and what specific metadata attributes indicate a correctly functioning AWS Database Encryption SDK implementation.

The AWS Command Line Tool for Verification

The primary command line tool used to verify client-side encryption configurations in DynamoDB is the standard AWS CLI (aws dynamodb).

Because client-side encryption occurs entirely within your application before data reaches DynamoDB, the database engine has no native knowledge of plaintext keys or encryption status. To verify that your client-side encryption rules are working correctly, you use the AWS CLI to retrieve the raw, stored item directly from DynamoDB and inspect its schema.

Step-by-Step Verification Using aws dynamodb get-item

To verify the stored data, execute the get-item command against your target table using the item's primary key:

aws dynamodb get-item \
    --table-name YourTableName \
    --key '{"PartitionKeyName": {"S": "YourKeyValue"}}'

When reviewing the JSON output returned by the command, check for the following indicators:

1. Attribute Data Types

Attributes protected by client-side encryption (configured via the AWS Database Encryption SDK or the older DynamoDB Encryption Client) will no longer appear as Strings (S), Numbers (N), or Maps (M). Instead, encrypted attributes are stored as binary ciphertext indicated by the "B" data type.

2. Encryption Metadata and Signatures

When client-side encryption is properly configured, the client library automatically adds tracking attributes to store the encryption context, material descriptions, and cryptographic signatures. Look for the presence of the following attributes in the CLI output:

  • :amzn-ddb-ese- attributes: The AWS Database Encryption SDK injects signature and header attributes (such as amzn-ddb-ese-none-sig or amzn-ddb-ese-map-sig) that validate the integrity and authenticity of the encrypted item.
  • Plaintext Verification: Verify that unencrypted partition and sort keys remain in their expected plaintext formats (S or N), while sensitive payload fields only appear in encrypted format.

Validating Decryption via the Application Layer

If an item's raw output contains binary blobs and cryptographic signature fields in aws dynamodb get-item, the client-side encryption configuration is active and functioning on write operations.

To ensure read operations function symmetrically, verify that your client application configured with the AWS Database Encryption SDK can successfully retrieve and decrypt the same item back into its original plaintext state. Attempting to read the item with a client lacking the required encryption material provider will result in a signature validation failure or an inability to decrypt the payload.
