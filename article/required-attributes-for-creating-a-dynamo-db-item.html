Required Attributes for Creating a DynamoDB Item

When creating a new item in Amazon DynamoDB, the only strictly required attributes are those that form the table's primary key. Because DynamoDB is a NoSQL database with a flexible schema, it does not enforce a rigid structure for non-key attributes. This article explains the exact primary key requirements, how table design dictates required fields, and the constraints applied when writing an item.

The Primary Key Requirement

DynamoDB requires every item to be uniquely identifiable. As a result, the attributes that compose the primary key defined during table creation are mandatory for every write operation, such as PutItem.

Depending on how your table is configured, the required attributes fall into one of two categories:

  1. Simple Primary Key (Partition Key Only): If the table is configured with a simple primary key, only the Partition Key (also referred to as the hash key) is required. Every new item must include this attribute, and its value must conform to the defined data type (String, Number, or Binary).

  2. Composite Primary Key (Partition Key and Sort Key): If the table is configured with a composite primary key, both the Partition Key and the Sort Key (also referred to as the range key) are strictly required. Omitting either attribute will cause the write operation to fail with a validation exception.

Schemaless Non-Key Attributes

Aside from the partition key and optional sort key, no other attributes are required by DynamoDB.

  • Flexibility: You can write an item containing only the primary key attributes, or include dozens of additional attributes.
  • Heterogeneous Data: Different items in the same table do not need to share the same non-key attributes or data types.
  • Secondary Indexes: Global Secondary Indexes (GSIs) and Local Secondary Indexes (LSIs) do not make attributes mandatory. If an item does not contain the attributes required by an index, DynamoDB simply does not project that item into the index (acting as a sparse index).

Key Constraints to Keep in Mind

While only primary key attributes are strictly required, they must meet specific conditions during item creation:

  • Non-Empty Values: Partition and sort key attributes cannot contain empty string values or empty binary values.
  • Correct Data Type: The value supplied for a key attribute must strictly match the data type declared in the table definition.
  • Size Limits: Partition key values have a maximum length of 2048 bytes, while sort key values have a maximum length of 1024 bytes.
