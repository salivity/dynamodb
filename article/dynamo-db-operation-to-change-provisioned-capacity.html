DynamoDB Operation to Change Provisioned Capacity

In Amazon DynamoDB, managing workload performance and controlling costs often requires adjusting throughput settings as application traffic fluctuates. This article identifies the specific API operation used to change provisioned read and write capacity limits dynamically, explains how it functions without interrupting database availability, and outlines key considerations for scaling table capacity in real time.

The UpdateTable Operation

The DynamoDB operation that allows you to change provisioned capacity limits dynamically is UpdateTable.

Using the UpdateTable API action, you can modify the provisioned throughput settings—specifically the Read Capacity Units (RCUs) and Write Capacity Units (WCUs)—for an existing table, as well as for any of its Global Secondary Indexes (GSIs).

How It Works

When you invoke UpdateTable, you pass the ProvisionedThroughput parameter containing the updated values for ReadCapacityUnits and WriteCapacityUnits.

Key characteristics of this operation include:

  • Zero Downtime: DynamoDB performs throughput modifications dynamically in the background. The table remains fully online and continues to process incoming read and write requests while the changes take effect.
  • Table State: While the throughput is being adjusted, the table or index status changes to UPDATING. Once the requested capacity is allocated, the status returns to ACTIVE.
  • Index Scaling: You can adjust the capacity of Global Secondary Indexes independently of the base table using the GlobalSecondaryIndexUpdates parameter within the same operation.

AWS CLI Example

You can trigger the UpdateTable operation via the AWS Command Line Interface (CLI) to update capacity on an existing table:

aws dynamodb update-table \
    --table-name ProductCatalog \
    --provisioned-throughput ReadCapacityUnits=20,WriteCapacityUnits=20

Automation with DynamoDB Auto Scaling

While UpdateTable can be invoked manually or through custom scripts, AWS also provides DynamoDB Auto Scaling. This feature monitors your application's actual traffic patterns via Amazon CloudWatch alarms and automatically executes the UpdateTable operation to scale capacity up or down based on defined target utilization thresholds.
