How to Archive DynamoDB Items Automatically

Managing data lifecycles in Amazon DynamoDB is essential for controlling storage costs and maintaining query performance. The most effective AWS mechanism to automatically archive older DynamoDB items involves combining DynamoDB Time to Live (TTL) with Amazon DynamoDB Streams and AWS Lambda (or Amazon Kinesis Data Firehose) to transfer expired records into Amazon S3. This article explains how these services work together to detect expired data and move it to cost-effective long-term storage without impacting application performance.

The Core Solution: DynamoDB TTL and Streams

DynamoDB does not directly move items into an archive bucket on its own; instead, it uses a native feature called Time to Live (TTL) to mark and delete expired items at no additional write cost. When paired with DynamoDB Streams, any item deleted by TTL is captured as an event, allowing downstream services to process and store that item in an archival destination like Amazon S3.

1. Amazon DynamoDB Time to Live (TTL)

TTL allows you to define a specific timestamp attribute on your items using the Unix epoch time format (in seconds). Once the current time exceeds the timestamp stored in this attribute, DynamoDB automatically marks the item for deletion. The background deletion process typically occurs within 48 hours of expiration without consuming provisioned read or write throughput.

2. Amazon DynamoDB Streams

To prevent expired items from being permanently lost, you enable DynamoDB Streams on the table. When TTL removes an item, a REMOVE event is emitted to the stream. The event contains metadata indicating that the deletion was initiated by the DynamoDB TTL service (identified by the userIdentity field containing PrincipalId: dynamodb.amazonaws.com).

3. AWS Lambda or Amazon Kinesis Data Firehose

A consumer service reads the stream events and writes the data to cold storage:

  • AWS Lambda: A Lambda function triggers on new stream records, filters for TTL deletions, formats the data, and writes the objects directly to Amazon S3.
  • Amazon Kinesis Data Firehose: For high-throughput tables, DynamoDB Streams or Amazon Kinesis data streams can route records into Kinesis Data Firehose, which batches and compresses the items before delivering them to Amazon S3.

4. Amazon S3 and S3 Glacier

Amazon S3 acts as the final archival repository. Once the data lands in an S3 bucket, S3 Lifecycle policies can automatically transition older archives to colder storage classes, such as S3 Glacier Flexible Retrieval or S3 Glacier Deep Archive, to minimize long-term storage expenses.

Implementation Steps

  1. Add a Timestamp Attribute: Update your application to write a TTL attribute (e.g., TimeToExist or ExpirationTime) formatted in Unix epoch seconds to each item.
  2. Enable TTL on the Table: In the DynamoDB console, manage TTL settings and select your designated timestamp attribute.
  3. Enable DynamoDB Streams: Configure the stream view type to New and old images to ensure the entire deleted item is available in the event record.
  4. Deploy the Archival Consumer: Create an AWS Lambda function with permissions to read from DynamoDB Streams and write to your designated Amazon S3 bucket.
  5. Filter and Save: Configure the function to verify that the deletion source is the TTL system, transform the JSON payload as needed, and store the file in Amazon S3.
