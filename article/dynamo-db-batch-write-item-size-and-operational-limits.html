DynamoDB BatchWriteItem Size and Operational Limits

Amazon DynamoDB provides the BatchWriteItem operation to put or delete multiple items across one or more tables in a single API call. This article outlines the exact operational size and item limits for a single batch write request, explains how DynamoDB handles unprocessed items, and highlights key constraints developers must consider when implementing batch operations.

Core Operational Limits for BatchWriteItem

When using the BatchWriteItem API in DynamoDB, a single request is subject to two primary operational constraints:

  • Maximum Request Size (Payload): A single BatchWriteItem request can be up to 16 MB in total size.
  • Maximum Number of Operations: A single request can contain up to 25 individual write actions (either PutItem or DeleteItem).

Additionally, individual DynamoDB items within the batch must adhere to the standard item size limit of 400 KB, including both attribute names and values.

Key Functional Constraints

  • Supported Operations Only: BatchWriteItem only supports PutItem and DeleteItem. It cannot be used to update existing items (UpdateItem is not supported in batch requests).
  • Non-Atomic Execution: Unlike TransactWriteItems, BatchWriteItem is not transactional. Individual operations within the batch are executed independently. If one write fails, others can still succeed.
  • Cross-Table Writes: A single batch request can write to multiple tables, provided the total item count does not exceed 25 and the payload remains under 16 MB.

Handling Partial Failures and Unprocessed Items

Because BatchWriteItem performs operations individually, it does not fail completely if only a few items cannot be written due to provisioned throughput constraints or transient network issues.

When partial failures occur:

  1. DynamoDB returns a response containing an UnprocessedItems map.
  2. The items that were successfully written are committed.
  3. The client application is responsible for inspecting the UnprocessedItems field and retrying those operations, typically using an exponential backoff algorithm.
