DynamoDB Consumed Capacity for Item Updates

When updating an attribute in Amazon DynamoDB to a larger size, consumed Write Capacity Units (WCUs) are determined by comparing the total size of the entire item before and after the modification. DynamoDB charges write capacity based on the larger of these two sizes, rounding up to the next 1 KB increment. Consequently, extending a string attribute increases the post-update item size, and if that size crosses a 1 KB threshold, the operation will consume additional WCUs.

The Larger Size Rule

DynamoDB does not charge solely for the differential data you append or modify. Instead, whenever you execute an UpdateItem operation, DynamoDB calculates the item’s total byte size at two points:

  1. Immediately prior to the update.
  2. Immediately after the update is applied.

The consumed capacity is always based on the larger of these two measurements. Because you are extending a string attribute to a larger length, the post-update representation will be larger than the pre-update representation, making the post-update size the governing factor for consumed capacity.

Calculating String and Item Size

To determine the post-update size, DynamoDB sums the storage requirements of all attributes in the item, not just the modified string:

  • Attribute Names: The length of each attribute name in UTF-8 bytes.
  • String Attribute Values: The length of the string value in UTF-8 bytes. Multi-byte characters (such as certain symbols or emojis) consume more than one byte each.
  • Item Overhead: DynamoDB adds 100 bytes of overhead per item to account for internal indexing and metadata.

Rounding Up to Write Capacity Units

Once the total byte size of the updated item is calculated, DynamoDB rounds the figure up to the nearest 1 KB boundary:

  • One WCU provides up to 1 KB of write capacity per second for standard writes.
  • An item measuring between 1 byte and 1,024 bytes consumes 1 WCU.
  • An item measuring between 1,025 bytes and 2,048 bytes consumes 2 WCUs.
  • Each additional 1,024 bytes adds 1 WCU.

Practical Example

Consider an existing item that is 900 bytes in total size (consuming 1 WCU if written).

If an UpdateItem operation appends 400 UTF-8 bytes of text to an existing string attribute:

  • Pre-update size: 900 bytes (falls in the 1 KB tier).
  • Post-update size: 1,300 bytes (900 bytes + 400 bytes).
  • Evaluation: DynamoDB selects the larger size (1,300 bytes).
  • Capacity Consumed: 1,300 bytes rounds up to the next 1 KB increment (2,048 bytes), resulting in a consumed capacity of 2 WCUs.

If the string was updated with only 50 bytes instead, the new total size would be 950 bytes. Because 950 bytes still falls within the initial 1 KB boundary, the update would only consume 1 WCU.
