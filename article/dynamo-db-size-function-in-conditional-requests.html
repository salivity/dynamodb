DynamoDB Size Function in Conditional Requests

Amazon DynamoDB allows developers to perform conditional write operations using the size function to evaluate the length or element count of an attribute before applying changes. When a conditional request containing a size comparison is submitted, DynamoDB retrieves the existing item, calculates the size of the target attribute based on its data type, and compares that value against a specified threshold using standard comparison operators. If the condition evaluates to true, the write operation proceeds; otherwise, DynamoDB halts the operation and returns a ConditionalCheckFailedException.

How the size Function Works

The size function takes an attribute path as an argument—expressed as size(path)—and returns a number representing the size of that attribute. The returned value depends on the attribute's data type:

  • String: Returns the length of the string in bytes (UTF-8 encoded), not the character count.
  • Binary: Returns the total number of bytes in the binary attribute.
  • String Set (SS), Number Set (NS), Binary Set (BS): Returns the number of distinct elements contained in the set.
  • List (L): Returns the number of elements in the list.
  • Map (M): Returns the number of key-value pairs in the map.

The size function cannot be evaluated directly on scalar Number, Boolean, or Null data types. Attempting to pass these data types to size results in a ValidationException.

Evaluation Workflow During Conditional Writes

When executing write operations—such as PutItem, UpdateItem, or DeleteItem—containing a ConditionExpression with size, DynamoDB follows a specific evaluation pipeline:

  1. Item Retrieval: DynamoDB identifies the target partition and reads the existing item directly from storage. Conditional checks are always performed with strong read consistency.
  2. Path Resolution: The engine checks whether the attribute specified inside size(path) exists within the existing item. If the path does not exist, the evaluation yields an error/false condition unless explicitly guarded by other conditions like attribute_exists.
  3. Metric Calculation: DynamoDB determines the data type of the resolved attribute and calculates the numeric size according to the rules defined above.
  4. Relational Evaluation: DynamoDB applies the comparison operator (=, <>, <, <=, >, >=) between the computed size and the comparator value (usually an expression attribute value).
  5. Execution or Failure:
    • If the condition evaluates to true, the mutation applies atomically to the item.
    • If the condition evaluates to false, the operation is rejected immediately, no data is written, and DynamoDB returns a ConditionalCheckFailedException.

Common Comparison Patterns

The size function is frequently used to enforce business constraints and prevent unbounded growth of document attributes:

  • Bounding Collection Sizes: Preventing a list from exceeding a specific capacity (e.g., size(log_entries) < :max_limit).
  • Restricting Payload Sizes: Ensuring uploaded strings or binary buffers do not exceed memory thresholds (e.g., size(payload) <= :max_bytes).
  • Checking for Emptiness: Ensuring that an array, set, or map contains elements before executing an update (e.g., size(tags) > :zero).

Capacity and Cost Considerations

Evaluating conditions with the size function does not consume separate read capacity units. Instead, the conditional check is factored into the write request. If the condition fails, DynamoDB still consumes write capacity units equivalent to the cost of reading the item to validate the condition.
