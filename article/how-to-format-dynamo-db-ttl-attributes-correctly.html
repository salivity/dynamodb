How to Format DynamoDB TTL Attributes Correctly

Amazon DynamoDB’s Time to Live (TTL) feature allows you to automatically delete expired items from your tables without consuming provisioned throughput. To ensure DynamoDB successfully identifies and purges expired records, the designated TTL attribute must adhere to specific formatting requirements. This guide covers the required data type, timestamp format, common implementation mistakes, and operational considerations to guarantee your items expire as expected.

Required Data Type and Format

For DynamoDB TTL to process an item, the target attribute must meet two strict criteria:

  1. DynamoDB Number Data Type (N): The attribute must be stored explicitly as a Number data type. Storing the timestamp as a String (S)—even if the string contains only numeric digits—prevents the TTL process from recognizing the value.
  2. Unix Epoch Time in Seconds: The value must represent the expiration timestamp in Unix epoch time format, measured in seconds elapsed since 00:00:00 UTC on January 1, 1970.

For example, an expiration date of January 1, 2026, at 00:00:00 UTC must be stored as:

{
  "ttl_timestamp": {
    "N": "1767225600"
  }
}

Common Formatting Pitfalls

  • Using Milliseconds Instead of Seconds: A frequent error occurs when developers use programming language defaults, such as JavaScript's Date.now() or Java's System.currentTimeMillis(), which output 13-digit millisecond timestamps. A 13-digit number evaluates to a date thousands of years in the future, meaning DynamoDB will not delete the item in your lifetime. Always convert milliseconds to seconds by dividing by 1,000 and rounding to the nearest integer.
  • Storing ISO-8601 Strings: Standard date-time strings (e.g., 2026-01-01T00:00:00Z) are not parsed by the TTL engine. Ensure your application logic converts standard dates into numeric epoch seconds before saving the record.
  • Negative or Extremely Past Values: While values far in the past may technically be expired, DynamoDB ignores TTL attributes with timestamps older than five years to prevent accidental data loss.

Deletion Behavior and Application Logic

DynamoDB runs TTL deletions as a background task to ensure it does not interfere with regular read and write workloads. As a result, items are typically deleted within 48 hours of their expiration time, though the process often completes much faster.

Because deletion is not instantaneous, expired items might still appear in read requests (GetItem, Query, or Scan). If your application requires strict expiration handling, implement a filter expression in your queries to hide records where the TTL attribute is less than or equal to the current epoch timestamp:

#ttl > :currentTime
