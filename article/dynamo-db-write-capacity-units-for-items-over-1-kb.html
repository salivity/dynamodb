DynamoDB Write Capacity Units for Items Over 1 KB

Amazon DynamoDB provisions and charges for throughput using capacity units, where writes are metered based on the size of the item being saved. For operations writing data larger than one kilobyte (KB), DynamoDB calculates write capacity consumption by rounding the total item size up to the next whole kilobyte increment. This article explains the exact formula DynamoDB uses to compute Write Capacity Units (WCUs) for larger writes, details how this applies to batch and transactional operations, and outlines key cost-optimization implications.

The Basic Calculation Rule

One Write Capacity Unit (WCU) represents one standard write per second for an item up to 1 KB in size. When an item exceeds 1 KB, DynamoDB determines the required WCUs using a straightforward rounding rule:

\[\text{WCUs Required} = \lceil \text{Item Size in KB} \rceil\]

DynamoDB calculates the total size of the item (including attribute names and values) and rounds up to the nearest 1 KB boundary. For example:

  • 0.8 KB Item: Consumes 1 WCU (falls within the baseline 1 KB limit).
  • 1.2 KB Item: Rounds up to 2 KB, consuming 2 WCUs.
  • 3.0 KB Item: Exactly 3 KB, consuming 3 WCUs.
  • 3.01 KB Item: Rounds up to 4 KB, consuming 4 WCUs.

Even a single byte beyond a 1 KB boundary incurs the cost of an entire additional WCU.

Calculating Batch Writes

When using the BatchWriteItem API operation, DynamoDB does not sum the sizes of all items together before calculating capacity. Instead, it meters each item individually:

  1. DynamoDB calculates the size of each item in the batch.
  2. It rounds each item up to the nearest 1 KB boundary.
  3. It adds the individual rounded values together to compute the total WCUs consumed.

For instance, writing two items sized at 1.2 KB and 1.1 KB in a single batch does not equal 2.3 KB rounded to 3 WCUs. Instead, Item 1 rounds up to 2 WCUs and Item 2 rounds up to 2 WCUs, consuming a total of 4 WCUs.

Transactional Writes

For ACID transactions performed via TransactWriteItems, DynamoDB requires two write capacity units per 1 KB of data. The calculation applies the same rounding logic first and then doubles the result:

\[\text{Transactional WCUs} = \lceil \text{Item Size in KB} \rceil \times 2\]

An item measuring 2.5 KB inside a transaction rounds up to 3 KB, which is then multiplied by 2, requiring 6 WCUs.

Cost Optimization Considerations

Because capacity scales directly with 1 KB increments, small reductions in item size can yield significant savings:

  • Attribute Name Shortening: DynamoDB measures the length of attribute names alongside values. Shortening repetitive attribute names can keep an item just below a kilobyte threshold.
  • Compression: For large text or binary payloads, compressing data into a binary attribute before writing can reduce the number of consumed 1 KB blocks.
  • Offloading Large Payloads: Storing large, rarely updated blobs in Amazon S3 and saving only the S3 object reference in DynamoDB ensures the DynamoDB item remains within the 1 KB baseline.
