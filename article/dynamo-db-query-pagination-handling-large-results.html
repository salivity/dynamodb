DynamoDB Query Pagination: Handling Large Results

Amazon DynamoDB processes large result sets by automatically dividing query responses into manageable chunks through a process called pagination. When a Query operation matches more data than the platform's default size limit or a client-specified item limit, DynamoDB returns a partial result along with a pagination token known as LastEvaluatedKey. By feeding this token back into subsequent requests as the ExclusiveStartKey, client applications can iteratively retrieve the remaining data across multiple network calls until the entire result set is consumed.

The 1 MB Size Boundary

DynamoDB imposes a strict 1 MB limit on the amount of data a single Query operation can return. This limit is evaluated against the raw size of the items read from the table, not the size after client-side transformations or network compression.

If a query matches data that exceeds 1 MB, DynamoDB immediately halts the read operation, packages the items read up to that point, and returns them to the caller. This boundary ensures that individual requests maintain predictable, single-digit millisecond latency and do not consume excessive system resources.

The Pagination Mechanism: LastEvaluatedKey and ExclusiveStartKey

DynamoDB uses a state-free token mechanism based on the primary key values of the table or index being queried:

  1. LastEvaluatedKey: When a query operation terminates before reading all matching items—either because it hit the 1 MB size limit or a defined Limit parameter—the response payload includes a LastEvaluatedKey. This attribute contains the primary key (partition key and, if applicable, sort key) of the last item evaluated during the request.
  2. ExclusiveStartKey: To fetch the next batch of records, the client submits a new Query request identical to the original, with the addition of the ExclusiveStartKey parameter set to the value of the received LastEvaluatedKey.

DynamoDB uses the ExclusiveStartKey to determine the exact point from which to resume the query, skipping the item represented by that key and continuing forward in the specified sort order. When a query reaches the end of the matching result set, the response omits the LastEvaluatedKey, signaling that all data has been fetched.

FilterExpressions and Pagination

A critical aspect of DynamoDB pagination is the interaction between FilterExpression and the 1 MB limit:

  • DynamoDB applies the query's partition key and sort key conditions first to identify the candidate items.
  • It reads items up to the 1 MB limit.
  • It then applies the FilterExpression to remove non-matching records after reading them from disk.

Because filtering occurs after the read operation, a query response might contain an empty Items array while still returning a LastEvaluatedKey. Applications must not rely on an empty item array as an indicator that the query is finished; the query is only complete when LastEvaluatedKey is absent from the response.

Implementing Pagination in Code

Processing paginated data requires an iterative loop:

  1. Initial Query: Send the Query request with the required key condition expression.
  2. Process Batch: Process the array of records returned in the Items field.
  3. Evaluate Continuation: Inspect the response for the presence of LastEvaluatedKey.
  4. Subsequent Calls: If LastEvaluatedKey exists, assign its value to ExclusiveStartKey in the parameters for the next call and repeat the process.
  5. Termination: Exit the loop once LastEvaluatedKey is null or undefined.

Most modern AWS SDKs provide built-in paginator abstractions (such as paginateQuery in the AWS SDK for JavaScript v3 or paginators in Boto3 for Python) that automate this loop, automatically extracting the token and yielding pages or individual items until exhaustion.
