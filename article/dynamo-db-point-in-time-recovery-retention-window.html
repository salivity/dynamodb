DynamoDB Point-in-Time Recovery Retention Window

Amazon DynamoDB Point-in-Time Recovery (PITR) provides continuous, automated backups for your database tables to protect against accidental writes or deletes. This article covers the maximum retention window supported by DynamoDB PITR, how the recovery timeline functions, and how to maintain backups beyond the native retention threshold.

The Maximum Retention Window: 35 Days

The maximum retention window supported by DynamoDB Point-in-Time Recovery is 35 days.

When PITR is enabled on a DynamoDB table, AWS continuously backs up your data and maintains a rolling 35-day recovery window. You can restore your table to any single second within this 35-day period, ending typically within five minutes of the current time.

Any data modifications older than 35 days expire automatically and fall outside the restorable window. The continuous backup timeline is bounded by two parameters:

  • EarliestRestorableDateTime: The earliest point in time to which you can restore the table, typically 35 days prior to the current time (or the time PITR was enabled, if enabled less than 35 days ago).
  • LatestRestorableDateTime: The most recent point in time to which you can restore the table, which is usually about five minutes prior to the present moment.

How Continuous Backups Work

DynamoDB PITR functions without consuming provisioned read or write throughput capacity, and it does not affect database performance or latency. When you execute a restore:

  • The restore operation creates a brand-new DynamoDB table.
  • The original source table remains completely untouched and operational.
  • You can adjust table settings—such as secondary indexes, provisioned capacity, and encryption keys—on the newly restored table.

If you disable PITR on a table, the backup timeline immediately clears, and all historical recovery points are permanently deleted. Re-enabling PITR starts a brand-new timeline beginning at that moment.

Long-Term Retention Beyond 35 Days

Because PITR strictly enforces the 35-day ceiling, it is designed for operational recovery rather than long-term data archiving or regulatory compliance.

To retain DynamoDB data beyond the 35-day limit, you must use on-demand backups:

  • DynamoDB On-Demand Backups: Manual or automated full table snapshots that persist until you explicitly delete them.
  • AWS Backup Integration: Centralized backup management that allows you to schedule recurring snapshots, configure lifecycle policies to transition data to cold storage, and retain backups for months or years.
