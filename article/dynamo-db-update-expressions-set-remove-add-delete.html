DynamoDB Update Expressions: SET, REMOVE, ADD, DELETE

Amazon DynamoDB uses update expressions within the UpdateItem API operation to modify existing item attributes or add new ones without needing to overwrite the entire item. These expressions rely on four core action clauses: SET, REMOVE, ADD, and DELETE. Each action targets specific data types and operational requirements, such as altering values, manipulating nested documents, adjusting numeric counters, or modifying sets. Understanding how DynamoDB processes these actions ensures precise, atomic, and cost-effective data modifications.

The SET Action

The SET action is the most versatile clause in DynamoDB update expressions. It creates an attribute if it does not already exist, or updates its value if it does.

  • Assigning Values: You can assign primitive values, maps, lists, or sets directly (e.g., SET #status = :val).
  • Nested Document Paths: SET can update specific elements within maps and lists using document paths (e.g., SET address.zipcode = :zip or SET favoriteColors[0] = :color).
  • Arithmetic Operations: It supports basic addition and subtraction on numeric types directly within the expression (e.g., SET viewCount = viewCount + :incr).
  • Built-in Functions: SET supports functions like if_not_exists(path, value) to set a fallback value if the attribute does not exist, and list_append(list1, list2) to concatenate lists.

The REMOVE Action

The REMOVE action deletes one or more attributes from an existing item or removes specific elements from a list.

  • Top-Level and Nested Attributes: Specifying an attribute path removes that attribute completely (e.g., REMOVE temporaryToken, metadata.debugInfo).
  • List Elements: Specifying an index removes an element from a list (e.g., REMOVE shoppingList[1]). When an element is removed, DynamoDB shifts all subsequent list elements down by one index to close the gap.

The ADD Action

The ADD action is restricted to only two data types: numbers and sets (String Sets, Number Sets, Binary Sets). It cannot be used with lists, maps, booleans, or plain strings.

  • Numbers (Atomic Counters): When applied to a numeric attribute, ADD acts as an atomic counter. If the attribute does not exist, DynamoDB creates it with the given value as its starting point. If it does exist, DynamoDB adds the positive or negative value to the current total (e.g., ADD loginAttempts :one). Note: AWS recommends using SET with arithmetic expressions over ADD for numeric modifications in newer applications.
  • Sets: When applied to a set, ADD appends the specified elements to the existing set if they are not already present (e.g., ADD tags :newTags). If the set attribute does not exist, DynamoDB creates a new set with those elements.

The DELETE Action

The DELETE action works exclusively on set data types (String Sets, Number Sets, and Binary Sets).

  • Removing Elements from Sets: Unlike REMOVE, which deletes an entire attribute, DELETE removes one or more individual elements from an existing set (e.g., DELETE blacklistedUsers :removedUsers).
  • Non-Existent Elements: If the values specified to be deleted do not exist within the target set, DynamoDB completes the operation without throwing an error. If all elements of a set are deleted, the attribute itself is removed because DynamoDB does not support empty sets.

Rules for Combining Actions

DynamoDB allows multiple actions to be combined into a single update expression (e.g., SET #a = :val1 REMOVE #b ADD #c :val2). However, several key constraints apply:

  • Each action keyword (SET, REMOVE, ADD, DELETE) can appear only once in the entire update expression string.
  • You cannot reference the exact same attribute across multiple action clauses within the same expression (for instance, you cannot SET #a and REMOVE #a in the same update).
  • All operations inside a single update expression are executed atomically as part of a single transaction on the item.
