DynamoDB Query Size Limits and Constraints

Amazon DynamoDB enforces distinct size limits on query operations to maintain consistent single-digit millisecond latency. The primary restriction is a 1 MB size limit on the total data returned in a single query request, alongside a 400 KB maximum limit on any individual item. This article details the specific attribute size boundaries applied during a DynamoDB query, how expressions affect data calculation, and how to handle queries that exceed these thresholds.

The 1 MB Response Limit

In Amazon DynamoDB, a single Query operation can fetch a maximum of 1 MB of data across all matching items. This limit applies to the combined total size of all attribute names and attribute values across the returned dataset.

Crucially, this 1 MB limit is evaluated before any FilterExpression is applied. If a query matches 1 MB of data, DynamoDB stops reading immediately and applies the filter to that specific batch. Even if the resulting dataset sent back to the client contains zero items after filtering, the operation still halts once the 1 MB boundary of evaluated items is reached.

Individual Item Limit (400 KB)

Any single item stored in DynamoDB—and therefore any item retrieved by a query—has a strict maximum size limit of 400 KB. This calculation includes:

  • The length of attribute names (in UTF-8 bytes).
  • The size of attribute values (based on data type, with strings measured in UTF-8 bytes and binary data measured directly in bytes).
  • A small overhead (typically 1 byte per attribute) for data type descriptors.

Because an item cannot exceed 400 KB, a single query result will contain anywhere from one item (if it approaches the 400 KB ceiling) to thousands of small items, up to the 1 MB total limit.

Impact of Projection Expressions

Using a ProjectionExpression allows you to retrieve only specific attributes rather than the entire item. However, this does not bypass the 1 MB read limit:

  • Read Capacity & Limit: DynamoDB still reads the entire item from the storage layer. Therefore, the 1 MB evaluation limit still counts the full size of the items matched by the key condition, not just the projected attributes.
  • Network Transfer: The primary benefit of a projection expression is reducing the network payload sent from DynamoDB to your application, lowering latency and transfer overhead.

Handling Size Limits with Pagination

When a query matches more than 1 MB of data, DynamoDB does not fail; instead, it truncates the result set and implements pagination:

  1. The response includes a LastEvaluatedKey attribute containing the primary key of the last processed item.
  2. To retrieve the remaining data, your application must issue a subsequent Query call passing this token into the ExclusiveStartKey parameter.
  3. This process continues iteratively until the query response no longer returns a LastEvaluatedKey, indicating that all matching items have been processed.
