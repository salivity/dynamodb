DynamoDB Batch Read Capacity for Eventual Consistency

Amazon DynamoDB determines consumed Read Capacity Units (RCUs) for batch operations by evaluating each requested item individually against standardized size thresholds and the selected consistency model. When executing a BatchGetItem operation with eventual consistency—which is the default setting—DynamoDB rounds each retrieved item's size up to the next 4 KB boundary and charges 0.5 RCUs per 4 KB chunk. This article explains the calculation mechanics, key operational rules, and step-by-step examples that govern how DynamoDB meters eventual consistency batch reads.

The Baseline RCU Definition

DynamoDB defines a single Read Capacity Unit based on strongly consistent reads:

  • Strongly Consistent Read: Consumes 1 RCU for an item up to 4 KB in size.
  • Eventually Consistent Read: Consumes 0.5 RCU for an item up to 4 KB in size.

Because eventual consistency provides a 50% discount compared to strong consistency, you get two 4 KB reads per 1 RCU.

Individual Item Evaluation Rule

A critical aspect of BatchGetItem is that DynamoDB does not sum the sizes of all items in the batch before calculating consumed capacity. Instead, it evaluates each item independently:

  1. Calculate the size of the retrieved item (including attribute names and values).
  2. Round up the item's size to the nearest multiple of 4 KB.
  3. Multiply each 4 KB increment by 0.5 RCU.
  4. Sum the resulting RCUs across all successfully retrieved items in the batch.

The formula for each item in an eventually consistent batch read is:

\[\text{RCUs per Item} = \left\lceil \frac{\text{Item Size in KB}}{4} \right\rceil \times 0.5\]

Calculation Example

Suppose a single BatchGetItem request retrieves three items with the following sizes under eventual consistency:

  • Item A: 2.5 KB
  • Item B: 5.8 KB
  • Item C: 9.1 KB

The capacity is calculated as follows:

  • Item A (2.5 KB): Rounds up to 4 KB. \[\left\lceil \frac{2.5}{4} \right\rceil \times 0.5 = 1 \times 0.5 = 0.5 \text{ RCU}\]
  • Item B (5.8 KB): Rounds up to 8 KB. \[\left\lceil \frac{5.8}{4} \right\rceil \times 0.5 = 2 \times 0.5 = 1.0 \text{ RCU}\]
  • Item C (9.1 KB): Rounds up to 12 KB. \[\left\lceil \frac{9.1}{4} \right\rceil \times 0.5 = 3 \times 0.5 = 1.5 \text{ RCUs}\]

Total Consumed Capacity: \(0.5 + 1.0 + 1.5 = 3.0\text{ RCUs}\).

If DynamoDB aggregated the sizes prior to rounding (totaling 17.4 KB, rounded to 20 KB), the cost would have been 2.5 RCUs. However, because each item is metered in isolation, the total comes to 3.0 RCUs.

Operational Limits and Edge Cases

  • Batch Limits: A BatchGetItem call can retrieve up to 100 items or 16 MB of data per request, whichever threshold is reached first.
  • Unprocessed Keys: If a table or partition exceeds its provisioned read throughput during a batch request, DynamoDB may return partial results along with an UnprocessedKeys element. DynamoDB only charges RCUs for the items that were successfully retrieved; unprocessed keys consume zero capacity until they are sent in a subsequent retry request.
  • Non-Existent Items: If a requested primary key does not exist in the table, DynamoDB still consumes capacity. The attempt is rounded up to 4 KB and charged as 0.5 RCU under eventual consistency.
