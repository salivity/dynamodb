DynamoDB Global Secondary Index Storage Metric

Monitoring storage consumption in Amazon DynamoDB is essential for capacity planning, cost management, and architecture optimization. This article details the specific Amazon CloudWatch metric used to track the storage space consumed by DynamoDB Global Secondary Indexes (GSIs), explains how it differs from primary table storage metrics, and provides key operational details regarding its reporting intervals and dimensions.

The CloudWatch Metric: GlobalSecondaryIndexSizeBytes

The CloudWatch metric that tracks the amount of storage space consumed by a DynamoDB Global Secondary Index is GlobalSecondaryIndexSizeBytes.

This metric reports the total size, in bytes, of the specified Global Secondary Index. Because a GSI contains a separate projection of the base table's data, its storage footprint is calculated and billed independently of the base table.

Key Metric Specifications

To properly query and interpret GlobalSecondaryIndexSizeBytes, use the following parameters:

  • Namespace: AWS/DynamoDB
  • Metric Name: GlobalSecondaryIndexSizeBytes
  • Units: Bytes
  • Dimensions:
    • TableName: The name of the parent DynamoDB table.
    • GlobalSecondaryIndexName: The name of the specific Global Secondary Index you are monitoring.

Reporting Frequency and Behavior

Like the base table storage metric (TableSizeBytes), GlobalSecondaryIndexSizeBytes is not updated in real time.

  • Update Interval: DynamoDB updates this metric approximately once every six hours.
  • Statistic: The recommended statistic to view is Average or Maximum over a long evaluation period (such as 6 hours or 1 day) due to the infrequent reporting schedule.

Differences Between Table and GSI Storage Metrics

Understanding how DynamoDB breaks down storage across its metrics ensures accurate monitoring:

  1. TableSizeBytes: Reflects the size of the base table along with any Local Secondary Indexes (LSIs). It does not include the data stored within GSIs.
  2. GlobalSecondaryIndexSizeBytes: Reflects only the data size of the specific GSI, including indexed attributes, projected non-key attributes, and secondary index structural overhead (approximately 100 bytes per item).

How to Access the Metric

You can view GlobalSecondaryIndexSizeBytes through several AWS interfaces:

  • AWS Management Console: Open the CloudWatch console, navigate to Metrics > DynamoDB > Table and Secondary Index Metrics, and select the metric associated with your table and GSI name.
  • AWS CLI: Run the aws cloudwatch get-metric-data command, specifying the AWS/DynamoDB namespace, GlobalSecondaryIndexSizeBytes metric, and the required TableName and GlobalSecondaryIndexName dimensions.
  • CloudWatch Alarms: You can create alarms based on this metric to alert your team when a GSI exceeds expected storage thresholds, helping avoid unexpected storage charges.
