How DynamoDB Enforces HIPAA and PCI-DSS Compliance

Amazon DynamoDB enforces security compliance standards like the Health Insurance Portability and Accountability Act (HIPAA) and the Payment Card Industry Data Security Standard (PCI-DSS) through a combination of built-in security controls, architectural isolation, and continuous auditing under the AWS Shared Responsibility Model. By providing automated encryption at rest and in transit, fine-grained access control, isolated networking, and comprehensive audit logging, DynamoDB enables organizations to store, process, and manage protected health information (PHI) and cardholder data (CHD) while adhering to strict regulatory requirements.

The Shared Responsibility Model

Compliance in DynamoDB operates under the AWS Shared Responsibility Model. AWS is responsible for the security of the cloud, which includes the physical infrastructure, hardware, host operating systems, and database engine software. The customer is responsible for security in the cloud, which involves properly configuring table access, defining data handling policies, managing encryption keys, and ensuring client-side security.

AWS undergoes regular third-party audits to maintain compliance status:

  • HIPAA: DynamoDB is a HIPAA-eligible service. Organizations can sign an AWS Business Associate Addendum (BAA) to store and process PHI legally.
  • PCI-DSS: DynamoDB is certified as a PCI-DSS Level 1 Service Provider, the highest level of assessment for service providers handling credit card data.

Data Encryption

Data protection is foundational to both HIPAA and PCI-DSS, which mandate that sensitive information be encrypted both while stored and while traveling across networks.

Encryption at Rest

DynamoDB provides zero-configuration, default encryption at rest using 256-bit Advanced Encryption Standard (AES-256). This protects primary table data, local and global secondary indexes, streams, global tables, backups, and Point-in-Time Recovery (PITR) data.

Organizations can choose between three AWS Key Management Service (AWS KMS) options to satisfy specific compliance controls:

  • AWS Owned Keys: Default keys managed entirely by AWS with no additional cost.
  • AWS Managed Keys: Keys stored in AWS KMS under the customer account, allowing audit tracking via AWS CloudTrail.
  • Customer Managed Keys (CMKs): Keys created, owned, and managed by the customer. CMKs enable rotation policies, granular key usage permissions, and cryptographically verifiable deletion, meeting strict PCI-DSS key management requirements (Requirements 3.5 and 3.6).

Encryption in Transit

DynamoDB endpoints enforce encrypted communication using Transport Layer Security (TLS 1.2 or higher). All read and write operations between client applications and DynamoDB APIs travel through encrypted channels, fulfilling PCI-DSS requirements to protect cardholder data transmitted across open, public networks.

Identity, Access, and Fine-Grained Permissions

Both compliance standards require strict enforcement of the principle of least privilege. DynamoDB integrates natively with AWS Identity and Access Management (IAM) to enforce access boundaries.

IAM Policies and Role-Based Access

Access to DynamoDB APIs must be explicitly granted via IAM policies. Root access is restricted, and applications must authenticate using temporary credentials supplied by IAM roles.

Fine-Grained Access Control (FGAC)

DynamoDB supports attribute-based and row-level access control. Using IAM policy conditions, administrators can restrict a user's or application's access down to:

  • Specific items based on the partition key value (e.g., ensuring a patient can only retrieve records matching their own Patient ID).
  • Specific attributes (columns), preventing unauthorized personnel from viewing sensitive fields like primary account numbers (PAN) or medical diagnosis codes.

Network Isolation with Amazon VPC Endpoints

To prevent sensitive data from traversing the public internet, DynamoDB supports VPC Endpoints powered by AWS PrivateLink.

  • Private Networking: Applications running within a Virtual Private Cloud (VPC) can connect to DynamoDB directly across private IP addressing routes.
  • Endpoint Policies: Security teams can attach custom policies to the VPC endpoint itself, controlling which specific DynamoDB tables can be accessed from that network boundary and preventing data exfiltration to unauthorized accounts.

Continuous Monitoring and Audit Logging

PCI-DSS Requirement 10 and HIPAA Security Rules mandate comprehensive audit trails for all actions taken on sensitive data. DynamoDB integrates with monitoring and logging services to satisfy these controls:

  • AWS CloudTrail: Automatically captures all administrative API actions (such as CreateTable, UpdateTable, or policy changes) with user identity, timestamps, source IP, and request parameters. CloudTrail can also log data-plane events (such as PutItem or GetItem) to maintain an exact audit trail of data access.
  • Amazon CloudWatch: Monitors database metrics, connection attempts, and unauthorized access failures in real time. Alarms can be configured to trigger automated responses or notify security personnel of suspicious activities.
  • AWS Config: Continuously monitors the configuration of DynamoDB tables to ensure compliance with predefined organizational baselines, such as verifying that encryption at rest and PITR are perpetually active.

Data Resilience and Recovery

Both HIPAA and PCI-DSS require business continuity and disaster recovery plans to ensure data is not lost or corrupted. DynamoDB addresses this through:

  • Automatic Multi-AZ Replication: Data is synchronously replicated across three Availability Zones within an AWS Region.
  • Point-in-Time Recovery (PITR): Provides continuous backups with per-second granularity, enabling restoration of data to any point within the preceding 35 days to mitigate accidental deletion or ransomware attacks.
  • On-Demand Backups: Allows the creation of full, long-term backups without performance degradation, aiding in regulatory archival requirements.
