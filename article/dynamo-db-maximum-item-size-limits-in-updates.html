DynamoDB Maximum Item Size Limits in Updates

Amazon DynamoDB enforces a strict 400 KB limit on the total size of an individual item, applying this restriction uniformly to full writes and partial updates alike. When executing an update via the UpdateItem API, DynamoDB evaluates the projected size of the entire item after all modifications are applied, rather than evaluating the update payload in isolation. This article explains how DynamoDB calculates item size, the evaluation process during partial updates, the error handling involved, and how capacity units are impacted.

The 400 KB Item Size Calculation

An item's size in DynamoDB is the sum of the lengths of all attribute names and their corresponding values. Attribute names are measured by their UTF-8 byte length, and attribute values are measured based on their data types:

  • Strings: The length of the string in UTF-8 encoded bytes.
  • Numbers: Approximately 1 byte per two significant digits, plus 1 byte for formatting (up to 21 bytes total).
  • Binary Data: The exact number of raw bytes.
  • Booleans and Nulls: 1 byte.
  • Lists and Maps: The sum of the nested elements plus 1 byte of overhead per element or key-value pair, along with 3 bytes of container overhead.

How Partial Updates Are Processed and Enforced

When you perform a partial update using an UpdateExpression (such as SET, ADD, or REMOVE actions), DynamoDB does not simply append changes to storage. Instead, it enforces the size constraint through a sequential, atomic lifecycle:

  1. Retrieve Current State: DynamoDB accesses the existing item from storage.
  2. Apply Modifications in Memory: The database engine applies the actions defined in the UpdateExpression to the existing attributes. If an attribute is removed, its size is deducted; if attributes are added or modified, their new byte counts are factored in.
  3. Validate Final Size: Before writing the changes to disk or replicating across Availability Zones, DynamoDB calculates the aggregate byte size of the entire resulting item.
  4. Commit or Abort: If the final item size is 400 KB or less, the write commits atomically. If the resulting item exceeds 400 KB, DynamoDB aborts the transaction entirely.

Error Handling

If a partial update pushes an item beyond 400 KB, DynamoDB rejects the request and throws a ValidationException with an error message stating that the item size has exceeded the maximum allowed size. Because DynamoDB updates are atomic, no attributes are updated, preventing data corruption or partially written states.

Impact on Consumed Capacity

The enforcement mechanism also dictates capacity consumption. For UpdateItem operations, DynamoDB consumes Write Capacity Units (WCUs) based on the larger of the two sizes: the item size before the update or the item size after the update, rounded up to the nearest 1 KB block. Even if your partial update only alters a few bytes, the write capacity charged reflects the entire size of the item.
