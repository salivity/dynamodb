DynamoDB Storage Pricing for Tables and Indexes

Amazon DynamoDB calculates storage pricing based on the cumulative disk space consumed by your base table items and secondary indexes, billed using a monthly per-gigabyte rate. Storage usage is continuously monitored throughout the month and averaged to determine your final bill, with the first 25 gigabytes per month included for free under the AWS Free Tier. Understanding how DynamoDB measures raw item data, attribute overhead, and index replication is critical for accurately projecting and optimizing your AWS storage costs.

How DynamoDB Computes Base Table Data Size

Storage calculation begins at the item level. DynamoDB does not simply measure the raw payload; it computes the size of each item by adding the byte size of attribute names, the byte size of attribute values, and a fixed overhead cost.

For each item stored in a table, DynamoDB calculates the size using the following components:

  • Attribute Names: The length of each attribute name in UTF-8 bytes.
  • Attribute Values: The size of the data depending on its data type:
    • Strings: The number of bytes using UTF-8 encoding.
    • Numbers: Variable-length encoding, roughly 1 byte per two significant digits plus 1 byte for formatting (up to 21 bytes).
    • Binary: The exact number of raw bytes.
    • Boolean: 1 byte.
    • Null: 1 byte.
    • Lists and Maps: The total size of all nested attribute names and values, plus 3 bytes of structural overhead per element.
  • Per-Item Overhead: A fixed 100 bytes of system overhead added to every item to manage metadata and indexing internal to DynamoDB storage architecture.

The sum of all items in the table determines the total base table storage footprint.

How Secondary Index Storage Is Computed

Secondary indexes replicate data from your base table and occupy independent storage space. The method of calculation depends on whether you use Global Secondary Indexes (GSIs) or Local Secondary Indexes (LSIs).

Global Secondary Indexes (GSIs)

GSIs maintain their own distinct partition and sort keys, as well as copies of projected attributes. For every item written to a base table that qualifies for a GSI, the GSI storage size includes:

  • The partition key and sort key of the GSI (attribute name and value bytes).
  • The primary key attributes of the base table (attribute name and value bytes).
  • Any additional attributes projected into the index (KEYS_ONLY, INCLUDE, or ALL).
  • A fixed 100 bytes of per-index-item overhead.

If you choose the ALL projection type, the GSI duplicates the entire base item plus its own keys, effectively doubling the storage consumption for that record.

Local Secondary Indexes (LSIs)

LSIs share the partition key with the base table but define an alternative sort key. For every item in an LSI, storage usage includes:

  • The base table partition key value (bytes).
  • The alternative sort key name and value (bytes).
  • All projected attributes for that index.
  • A fixed 100 bytes of per-index-item overhead.

LSI data is grouped with the base table data in the same storage partition, meaning the combined size of a base item and all its corresponding LSI entries counts against the 10 GB item collection limit.

Billing and Table Classes

DynamoDB calculates hourly storage usage by taking snapshots of your total storage (base table plus all GSIs and LSIs) and computes a monthly average expressed in GB-Months.

Pricing depends on the selected DynamoDB table class:

  • DynamoDB Standard: Designed for active workloads where throughput makes up the majority of costs. Storage is charged at a standard rate per GB-month after the 25 GB free tier.
  • DynamoDB Standard-Infrequent Access (DynamoDB Standard-IA): Designed for workloads storing massive volumes of data that are rarely accessed. Storage costs are discounted by roughly 60% compared to Standard, though read and write throughput costs are higher.

To determine your total storage cost, DynamoDB multiplies the average total gigabytes stored across base tables and secondary indexes by the regional per-gigabyte rate for the chosen table class.
