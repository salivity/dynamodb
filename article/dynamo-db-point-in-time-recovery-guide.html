DynamoDB Point-in-Time Recovery Guide

Amazon DynamoDB provides continuous, automated backups through its Point-in-Time Recovery (PITR) feature. This capability safeguards your DynamoDB tables against accidental write or delete operations by giving you the ability to restore table data to any single second within the preceding 35 days.

What is Point-in-Time Recovery (PITR)?

The feature in DynamoDB that enables recovery back to a specific second is officially called Point-in-Time Recovery (PITR).

Once enabled, PITR runs continuously in the background without requiring manual intervention. DynamoDB maintains incremental backups of your data, allowing you to choose any point in time between the moment PITR was enabled and the current time, going back up to 35 days. The restoration precision is granular to the exact second.

Key Characteristics of PITR

  • Second-Level Granularity: You can specify a timestamp down to the hour, minute, and second (YYYY:MM:DD HH:MM:SS) to recover your data to the moment just before an accidental modification or deletion occurred.
  • Zero Impact on Performance: PITR operates without consuming the read or write capacity units provisioned for your table. It does not degrade production database performance or availability during backup operations.
  • Restoration to a New Table: When you initiate a point-in-time restore, DynamoDB restores the data to an entirely new table. This ensures your existing table remains untouched while giving you full control over verification, testing, and DNS or application cutovers.
  • Included Components: The restore process recreates the primary key schema, local secondary indexes (LSIs), global secondary indexes (GSIs), and encryption settings on the new table. (Note: IAM policies, CloudWatch alarms, and auto-scaling policies must be configured on the restored table afterward).

How to Enable PITR

PITR can be enabled on any DynamoDB table via the AWS Management Console, the AWS Command Line Interface (CLI), or AWS SDKs.

Using the AWS CLI, you can enable continuous backups on an existing table with the following command:

aws dynamodb update-continuous-backups \
    --table-name YourTableName \
    --point-in-time-recovery-specification PointInTimeRecoveryEnabled=true

To verify the status of PITR on a table:

aws dynamodb describe-continuous-backups \
    --table-name YourTableName

When to Use PITR

PITR is primarily designed for disaster recovery scenarios caused by human error or application logic bugs, such as an errant script deleting customer records or a faulty deployment corrupting database fields. It serves as a continuous safety net alongside DynamoDB on-demand backups, which are typically used for long-term data archiving and compliance needs.
