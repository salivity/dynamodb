What Happens When DynamoDB Exceeds the 1MB Limit

When an Amazon DynamoDB Query or Scan operation exceeds the maximum payload size of 1 megabyte (MB), DynamoDB truncates the response, returns only the items evaluated up to that point, and provides a LastEvaluatedKey. This built-in cutoff prevents network latency spikes and ensures predictable performance. To retrieve the remaining data, applications must implement pagination by feeding the LastEvaluatedKey back into subsequent requests until DynamoDB signals that no items remain.

The 1MB Evaluation Threshold

DynamoDB enforces a hard 1MB size limit on the data evaluated per single operation. This limit is calculated based on the total uncompressed size of the items read from the table, not the size of the data serialized into the HTTP response.

When an operation begins:

  1. DynamoDB reads items sequentially based on the partition key and sort key conditions.
  2. It accumulates the raw data size of each evaluated item.
  3. Once the accumulated size reaches 1MB, DynamoDB halts execution immediately—even if there are more matching items in the partition.

The Role of LastEvaluatedKey

When an operation stops at the 1MB mark, the response payload includes a property named LastEvaluatedKey. This key contains the primary key attributes (partition key and, if applicable, sort key) of the last item processed before hitting the threshold.

If LastEvaluatedKey is present in the response, the operation is incomplete. If LastEvaluatedKey is empty or absent, DynamoDB has processed all matching records.

How to Paginate Results

To fetch the next batch of items, your application must issue a new query request that includes the ExclusiveStartKey parameter set to the value of the LastEvaluatedKey from the previous response.

The workflow proceeds as follows:

  1. Send the initial Query request.
  2. Process the returned Items array.
  3. Check the response for LastEvaluatedKey.
  4. If LastEvaluatedKey exists, issue another Query with ExclusiveStartKey = LastEvaluatedKey.
  5. Repeat this loop until LastEvaluatedKey is no longer returned.

Most modern AWS SDKs provide built-in paginator utilities (such as paginateQuery in AWS SDK for JavaScript v3 or Paginators in Boto3) that automate this loop.

How Filter Expressions Affect the Limit

A common point of confusion is the behavior of FilterExpression. DynamoDB evaluates the 1MB limit before applying filter expressions.

The evaluation order is:

  1. Read items matching the primary key condition until 1MB of data is reached.
  2. Apply the FilterExpression to remove non-matching items from the batch.
  3. Return the remaining items along with a LastEvaluatedKey.

Because filtering happens after the data is read, a query can consume 1MB of data, filter out every single item, and return an empty Items: [] array alongside a LastEvaluatedKey. Applications must never assume an empty items list marks the end of the query; pagination must continue as long as LastEvaluatedKey is present.

Strategies to Minimize 1MB Truncation

  • Narrow Key Conditions: Use specific sort key ranges (begins_with, between, >, <) to prevent DynamoDB from evaluating unnecessary records.
  • Set a Custom Limit: Define a smaller item limit (e.g., 20 or 50 items) for UI-driven pagination rather than letting queries run to the 1MB ceiling.
  • Store Large Payloads in S3: Keep large, infrequently searched attributes in Amazon S3 and store only the S3 object URL in DynamoDB to keep item sizes small and fit more records into a single read.
