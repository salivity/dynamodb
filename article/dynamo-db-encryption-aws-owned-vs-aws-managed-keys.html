DynamoDB Encryption: AWS Owned vs AWS Managed Keys

Amazon DynamoDB automatically encrypts all user data at rest to protect sensitive information using cryptographic keys. When configuring encryption at rest, administrators can choose between different key types managed by AWS Key Management Service (AWS KMS) or internal AWS systems. This article examines how DynamoDB manages data encryption keys by comparing AWS owned keys and AWS managed keys, detailing their architectural differences, visibility, cost impacts, and auditing capabilities.

Understanding DynamoDB Encryption at Rest

DynamoDB uses envelope encryption to protect data. In envelope encryption, raw table data is encrypted with a unique data encryption key (DEK), and the DEK is subsequently encrypted using a top-level Key Management Service key (or root key). When accessing data, DynamoDB decrypts the DEK and caches it in memory for a limited duration to execute operations efficiently without querying the key store on every single request.

The primary distinction between AWS owned keys and AWS managed keys lies in who owns the key, where it resides, how access is audited, and how associated costs are billed.

AWS Owned Keys

AWS owned keys are encryption keys that are created, maintained, and operated directly by DynamoDB within AWS's internal service infrastructure. They do not exist within a customer's AWS account.

  • Key Management: AWS completely handles the lifecycle of owned keys, including generation, rotation, access management, and retirement.
  • Visibility: These keys do not appear in your AWS KMS console, and you cannot view key metadata or policies through the KMS API.
  • Access Control: You cannot apply key policies, IAM restrictions, or grants to AWS owned keys. Permissions to access the table data are governed solely by standard DynamoDB IAM policies.
  • Auditing: Usage of AWS owned keys does not generate KMS events in AWS CloudTrail. While DynamoDB table access itself can be logged, the underlying cryptographic operations remain opaque to the customer.
  • Cost: AWS owned keys are free of charge. There are no monthly key storage charges or KMS API request fees associated with encrypting or decrypting your table data.

AWS Managed Keys

AWS managed keys are KMS keys created automatically in a customer’s account when using a service that integrates with AWS KMS. For DynamoDB, this key is labeled with the alias aws/dynamodb.

  • Key Management: AWS automatically provisions and manages the aws/dynamodb key on behalf of your account. AWS also handles automatic annual key rotation for this key type.
  • Visibility: AWS managed keys reside in your account and are visible under the "AWS managed keys" section in the AWS KMS console or via the KMS API.
  • Access Control: You can view the key policy, but you cannot modify it. IAM policies can, however, be configured to control who within your account has permission to use the key in conjunction with DynamoDB actions.
  • Auditing: Every time DynamoDB requests a data key or decrypts data using the aws/dynamodb key, the action is logged in AWS CloudTrail. This provides a transparent audit trail detailing when, why, and by whom cryptographic calls were made.
  • Cost: The aws/dynamodb key does not incur a monthly key storage fee. However, AWS KMS API calls (such as GenerateDataKey and Decrypt) that exceed the AWS KMS free tier will generate standard KMS request charges on your bill.

Choosing the Right Key Type

Selecting between an AWS owned key and an AWS managed key depends on your organization's compliance and operational requirements:

  • Choose an AWS owned key if your primary objectives are cost optimization and simplicity. It provides standard encryption at rest without adding any operational overhead or KMS API request charges to your monthly bill.
  • Choose an AWS managed key if your organization requires strict compliance, regulatory adherence, or auditing capabilities. Because interactions with the key are logged to AWS CloudTrail, security teams can verify and monitor key usage across all table operations.
