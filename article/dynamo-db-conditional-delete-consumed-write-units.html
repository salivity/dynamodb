DynamoDB Conditional Delete Consumed Write Units

When executing a conditional delete in Amazon DynamoDB, consumed Write Capacity Units (WCUs) are determined by both the outcome of the condition check and the size of the targeted item. Regardless of whether the condition succeeds or fails, DynamoDB consumes write capacity to evaluate the request. This guide breaks down the exact rules DynamoDB uses to meter consumed write capacity for conditional delete requests under different scenarios.

Baseline Write Capacity Unit (WCU) Calculation

For standard provisioned tables, one Write Capacity Unit (WCU) represents one write per second for an item up to 1 KB in size. Any item larger than 1 KB is rounded up to the nearest 1 KB multiple. On-demand capacity mode calculates write request units (WRUs) using the exact same item size rules, where one WRU corresponds to one write up to 1 KB.

Scenario 1: The Condition Evaluates to True (Successful Delete)

When the conditional expression evaluates to true, DynamoDB removes the item from the table.

  • Consumed Capacity: DynamoDB charges WCUs based on the full pre-existing size of the item being deleted.
  • Calculation: The size of the item (attributes and attribute names) is rounded up to the next 1 KB increment.
  • Example: Deleting a 2.3 KB item consumes 3 WCUs.
  • Secondary Indexes: If the item contains attributes that are projected into Global Secondary Indexes (GSIs), DynamoDB also consumes write capacity on each affected GSI to delete the corresponding index entries.

Scenario 2: The Condition Evaluates to False (Item Exists)

If the targeted item exists in the table but does not satisfy the specified ConditionExpression, DynamoDB rejects the operation and throws a ConditionalCheckFailedException.

  • Consumed Capacity: DynamoDB still consumes write capacity because it had to read and evaluate the item to perform the conditional write operation.
  • Calculation: The consumed write capacity equals the size of the existing item evaluated, rounded up to the nearest 1 KB boundary.
  • Example: Attempting to conditionally delete a 3.7 KB item where the condition fails consumes 4 WCUs.
  • Secondary Indexes: Because the item was not deleted, no GSIs are modified, and zero capacity is consumed on secondary indexes.

Scenario 3: The Condition Evaluates to False (Item Does Not Exist)

If you attempt a conditional delete on an item where the primary key does not exist in the table:

  • Consumed Capacity: DynamoDB cannot evaluate existing item data, but it still expends resources verifying that the item is missing against the condition.
  • Calculation: DynamoDB consumes a baseline of 1 WCU (or 1 WRU in on-demand mode).
  • Secondary Indexes: No index capacity is consumed.

Scenario 4: Conditional Deletes in Transactions

If a conditional delete is executed as part of a TransactWriteItems operation:

  • DynamoDB performs transactional operations using two-phase commits, which doubles the write capacity cost.
  • A successful conditional delete consumes 2 WCUs per 1 KB of item size.
  • If a transaction is canceled due to a failed conditional check within the transaction, write capacity units are consumed based on the size of the evaluated items multiplied by two.
