DynamoDB Stream Parameter for Item Images

Amazon DynamoDB Streams capture a time-ordered sequence of item-level modifications in a DynamoDB table. This article covers the specific parameter that dictates whether modified item data appears as old images, new images, or both: the StreamViewType setting. Understanding this configuration ensures downstream applications receive the precise payload needed for processing without incurring unnecessary overhead.

The StreamViewType Parameter

The parameter that controls which images appear in a DynamoDB stream is StreamViewType. When enabling DynamoDB Streams on a table, StreamViewType determines what information is written to the stream record whenever an item is created, updated, or deleted.

Supported StreamViewType Values

DynamoDB provides four distinct options for the StreamViewType parameter:

  • KEYS_ONLY: Only the key attributes (partition key and sort key, if applicable) of the modified item are written to the stream record.
  • NEW_IMAGE: The entire item, as it appears immediately after it was modified, is written to the stream record.
  • OLD_IMAGE: The entire item, as it appeared immediately before it was modified, is written to the stream record.
  • NEW_AND_OLD_IMAGES: Both the entire item prior to modification and the entire item following modification are written to the stream record.

Choosing the Right Setting

The choice of StreamViewType depends on how downstream consumers (such as AWS Lambda, Amazon Kinesis, or custom worker services) interact with table changes:

  • Audit Logging and History Tracking: Use NEW_AND_OLD_IMAGES when consumers need to compare previous states against current states to calculate diffs or track granular field changes over time.
  • Search Indexing and Cache Invalidation: Use NEW_IMAGE when updates only require syncing the latest state to an external search cluster (such as OpenSearch) or a caching layer.
  • Archiving Deletions: Use OLD_IMAGE if your primary goal is capturing records as they existed right before deletion.
  • Minimalist Notification Systems: Use KEYS_ONLY when consumers only need an event trigger to query the table directly or run a lightweight process without consuming payload bandwidth.

How to Configure StreamViewType

StreamViewType is configured at the time a stream is enabled. It can be defined using the AWS Management Console, AWS CLI, AWS SDKs, or Infrastructure as Code (IaC) tools such as AWS CloudFormation or Terraform.

AWS CLI Example

When enabling a stream on an existing table via the AWS CLI, specify the StreamSpecification object with the desired StreamViewType:

aws dynamodb update-table \
    --table-name YourTableName \
    --stream-specification StreamEnabled=true,StreamViewType=NEW_AND_OLD_IMAGES

AWS CloudFormation Example

In AWS CloudFormation, define the property under StreamSpecification:

Type: AWS::DynamoDB::Table
Properties:
  TableName: YourTableName
  StreamSpecification:
    StreamViewType: NEW_AND_OLD_IMAGES

Selecting the appropriate StreamViewType minimizes the data processed by downstream stream consumers and guarantees that all required item attributes are accessible without additional read operations against the primary table.
