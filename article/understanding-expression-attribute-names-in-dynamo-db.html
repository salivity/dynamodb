Understanding ExpressionAttributeNames in DynamoDB

In Amazon DynamoDB, the ExpressionAttributeNames parameter allows developers to define substitution tokens (placeholders) for actual attribute names in query, scan, and update requests. This article explains the core functions of ExpressionAttributeNames, including resolving conflicts with DynamoDB reserved keywords, handling attribute names with special characters, and querying deeply nested document paths.

Handling Reserved Keywords

DynamoDB maintains a comprehensive list of reserved keywords—such as status, year, date, percent, and name. If you attempt to use these words directly in query expressions (such as KeyConditionExpression, FilterExpression, or ProjectionExpression), DynamoDB throws a syntax error (ValidationException).

ExpressionAttributeNames solves this by allowing you to map an alias starting with a pound sign (#) to the reserved word.

For example, to query an item where the partition key is year:

{
  "TableName": "Movies",
  "KeyConditionExpression": "#yr = :yearValue",
  "ExpressionAttributeNames": {
    "#yr": "year"
  },
  "ExpressionAttributeValues": {
    ":yearValue": { "N": "2023" }
  }
}

DynamoDB substitutes #yr with year internally before executing the query.

Supporting Special Characters and Spaces

DynamoDB attribute names can technically contain characters that conflict with expression parsing logic, such as dots (.), dashes (-), and spaces.

In DynamoDB syntax, a dot represents a path delimiter for nested attributes. If an attribute name contains an actual dot (e.g., customer.id), the expression engine will interpret it as an object named customer containing a property named id. Using an expression attribute name isolates the dot as part of the literal attribute name:

"ExpressionAttributeNames": {
  "#cid": "customer.id"
}

Accessing Nested Document Paths

When querying attributes inside nested JSON structures (maps and lists), ExpressionAttributeNames provides a clean way to traverse documents without syntax collisions.

If a document has a map named Order with a nested field named Status, and both are reserved or require aliasing, you combine the placeholders:

"ProjectionExpression": "#ord.#st",
"ExpressionAttributeNames": {
  "#ord": "Order",
  "#st": "Status"
}

Summary of Usage

The ExpressionAttributeNames parameter is evaluated before the query runs. Its use is mandatory whenever:

  • An attribute name matches a DynamoDB reserved keyword.
  • An attribute name contains characters that interfere with expression syntax parsing.
  • Dynamic query building requires safe parameterization of field names.
